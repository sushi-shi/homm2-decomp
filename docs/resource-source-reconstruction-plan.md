# Resource source reconstruction plan

Status: **DEFERRED**. This plan does not activate source-level resource compilation.
The extracted canonical `build/link/HEROES2W.res` remains the linker input and byte
oracle until every phase below has been completed and audited.

## Principles

- Use typed resource parsers and serializers; do not manipulate resource structures
  with ad hoc byte or text substitutions.
- Preserve the extracted `.res` as the authoritative oracle throughout reconstruction.
- Recover only names and numeric values supported by retail evidence.
- Compare structured identities and ordering before investigating tool-generated bytes.

## Phases and deliverables

1. **Inventory the canonical records.** Record all 12 extracted leaves by type, name,
   language, ordering, header flags, payload size, and payload hash.
2. **Recover stable identifiers.** Create `resource.h` only after resource IDs and names
   are proven stable. Preserve numeric IDs where no supported symbolic name is known.
3. **Reconstruct menus.** Decompile all six menus while preserving `MENU` versus
   `MENUEX`, item flags, item order, help IDs, names, numeric IDs, and languages.
4. **Reconstruct the dialog.** Preserve `DIALOG` versus `DIALOGEX`, styles, extended
   styles, font metadata, control order, control IDs, and binary alignment.
5. **Reconstruct version data.** Recover the complete `VERSIONINFO` hierarchy, fixed
   binary fields, string tables, translations, and original child ordering.
6. **Reconstruct icons.** Convert the two group-icon records and two icon payloads into
   editable `.ico` or equivalent source assets, then add explicit RC declarations that
   reproduce the proven group and payload identities.
7. **Recover the resource toolchain.** Identify and use a matching VC-era `RC.EXE`,
   including the retail code page and language flags. Record the exact tool version and
   invocation.
8. **Compile source resources.** Compile `heroes.rc` to `heroes.res` in an isolated
   target. Do not replace the extracted canonical resource in the normal link yet.
9. **Compare compiled records.** Require exact record identities, ordering, header
   flags, and payload bytes against the extracted canonical `.res` before activation.
10. **Activate and link.** Replace the extracted input only after the compiled resource
    passes the record audit. Require exact `.rsrc` semantics, raw and virtual sizes,
    characteristics, and section order. Record any unavoidable tool-generated metadata
    separately from semantic fields.

## Non-goals

- No current activation of RC source in the normal build or link.
- No copying of the retail raw `.rsrc` section.
- No padding objects, forced RVAs, or section-address compensation.
- No guessed symbolic resource names.
