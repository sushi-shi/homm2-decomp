# Resource source reconstruction

Status: **DONE** (2026-08-24). The linker input `build/link/HMM2PL.res` is
compiled from source by the era resource compiler on every build, and a
byte-exact gate against the retail image guards it. The wholesale-extracted
`.res` is no longer a link input; extraction survives only as the retail half
of the gate comparison.

## Delivered state

- `res/HMM2PL.rc` — all ten retail resources as reviewed rc grammar: the six
  menus (`MNUADV`, `MNUADVD`, `MNUDFLT`, `MNUCMBT`, `MNUTOWN`, `MNUTOWND`),
  the `HEROES` About dialog, the `HEROES` icon statement, and the
  `1 VERSIONINFO` block. Statement order is retail payload order. All
  resources are `LANGUAGE 0x19, 0x1` (1049); Cyrillic cp1251 text is carried
  as `\ooo` octal escapes under `#pragma code_page(1251)`, so the file is pure
  ASCII. Numeric IDs are preserved as numbers — no symbolic `resource.h` names
  are invented (the retail image names none).
- `res/heroes.ico` — the one retail binary: the 32x32 16-color program icon,
  rebuilt as an ordinary `.ico` container from the retail `RT_ICON` payload
  and `RT_GROUP_ICON` directory. It is retail artwork, so it is **gitignored
  and materialized** from the locally supplied `build/orig/HMM2PL.exe` by
  `rc_res.py` on every resource build; `rc.exe` splits it back into exactly
  those two records.
- `scripts/homm2/build/rc_res.py` — compiles the `.rc` with the era
  `RC.EXE` 5.00 + `RCDLL.DLL` (from the pinned VS6 Enterprise base disc)
  under wine, then byte-compares every compiled payload (type, name,
  language, bytes, order) against `build/orig/HMM2PL.exe` in both
  directions. Any drift fails the build. The report lands at
  `build/link/HMM2PL.resources.json`.
- ninja's `link_resources` edge runs that driver; `homm2 link --rsrc` and
  `homm2 link --transform` consume the compiled `.res`. The `--transform`
  whole-file SHA-256 assertion additionally proves the linked `.rsrc` section
  byte-exact end to end.

## Corrections to the original inventory

The plan's draft inventory expected twelve leaves with two icon groups; the
retail image carries **ten**: one `RT_ICON` + one `RT_GROUP_ICON`, one
`RT_DIALOG`, six `RT_MENU` (the four 282-byte menus are byte-identical
copies under different names), and one `RT_VERSION`.

## Principles (unchanged, all honored)

- Typed resource parsers and serializers; no ad hoc byte or text substitutions.
- Only names and numeric values supported by retail evidence.
- Structured identities and ordering compared before tool-generated bytes.
- No copying of the retail raw `.rsrc` section; no padding objects, forced
  RVAs, or section-address compensation; no guessed symbolic resource names.

## Provenance note

`scripts/toolchain/create-toolchain-release.py` packages the era RC pair from
`COMMON/MSDEV98/BIN` on the pinned VS6 Enterprise base disc. The release
builder and `rc_res.py` both verify their SHA-256s; the latter additionally
proves their ten compiled payloads byte-exact against retail on every resource
build.
