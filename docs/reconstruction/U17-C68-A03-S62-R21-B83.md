# COMMAND: packet ownership, conversions, control flow and buffer contracts

The complete 3263-line TU, all 36 physical functions, private enum/macro
domains, fifteen EOF globals and complete 48-line recovered header were read.
Parent: `34b6e303`. Each function has all ten verdicts and its own substantive
note in [the function ledger](functions.tsv); file coverage is separately hashed.

## U17: recover the actual network owner

The old `CombatRemotePacket` was a 25-byte view. Its first byte was misleadingly
named `messageLength`, two header regions were called reserved, and a pointer
to its first action word was reinterpreted as chat text.

The complete producer and receiver prove a different owner: the 256-byte
`RemoteMessage` format, with nine header bytes and a 247-byte payload. COMMAND
now models the actual fields and command-gated text/action alternatives:

| Offset | Field | Extent |
| ---: | --- | ---: |
| 0 | signed sender | 1 |
| 1 | message ID | 4 |
| 5 | message type | 1 |
| 6 | command | 1 |
| 7 | payload size | 2 |
| 9 | four action words or chat text | 16 / 247 |

`TransmitRemoteData` constructs this header and copies the supplied payload;
`GetRemoteData` copies 256 bytes to the real 268-byte `rcvBufOut` owner and
returns it. Their complete 466/221 retail bytes, sites and targets pass
independent checks. `PopNetBox(text, netPlayer)` uses its second argument to
select a network player, not a byte length. `Main` therefore uses
`PopNetBox(packet->text, packet->sender)`. The wire-to-packet reinterpretation
remains a genuine representation boundary. This is not owner recovery by
subtracting a member offset, and no object allocation is enlarged: COMMAND
only holds a pointer view of the existing receive storage.

All 98 native objects remain identical in function bytes, allocated sections
and canonical ordered relocation topology after this header recovery. The
union describes a real tagged protocol; reducing union counts would be the
wrong objective here. `Main` still does not validate sender range, payload
size, text termination or action-domain values. Those transport contracts
remain open; this source-layout recovery is not network hardening.

## C68 and A03: retained changes

Nine scalar casts are removed: six assignments into the signed-byte direction
map, one unsigned-byte spell icon passed to an `i16` parameter, one unsigned-byte
portrait already promoted to `int` in varargs, and an integer random numerator
whose denominator is already `100.0f`. Together with U17's text cast, that is
ten written casts removed in this batch. Allocator, wire, enum-domain and real
numeric truncation/ratio conversions remain.

Two seemingly avoidable casts in `GetCommand` are **not** removed. Both the
cast-free integer conditional and the typed-command conditional preserve
1014 bytes and diagnostic topology but change native text. The original
byte-valued conditional feeding the command conversion remains recorded.

`SetCombatDirections` previously flattened `&m_adjacency[0][0]` beyond the
first six-element row. The real object is a 117x6 array; the retained expression
is `m_adjacency[targetHex][direction_28]`. Both direct-row and row-pointer arms
preserve all 1880 bytes and ordered relocation semantics. This fixes the
subarray ownership expression without claiming that arbitrary incoming indices
are safe. No padding array or overlapping alias is introduced.

## B83: proven capacities and remaining domains

[The executable evidence check](check-command-evidence.py) pins the genuine
retail image, all twenty numeric operands, every private string operand and
the actual artifact/spell/battle-result tables. Buffer bounds include NUL:

| Text | Conservative required bytes | Actual capacity |
| --- | ---: | ---: |
| Artifact name (103 entries, no format directives) | 29 | 60 |
| Spell name (65 entries) | 21 | 200 |
| Victory experience suffix | 114 | 152 |
| Combined victory / loss | 129 / 61 | 768 |
| Eagle Eye / surrender | 114 / 116 | 768 |
| Ballista description / three-part global text | 101 / 313 | 300 / 768 |

Hero formatting assumes a NUL within the real 13-byte name field. Ballista
numeric bounds allow arbitrary signed-32-bit values; fixed table IDs and live
town/widget/resource owners are still required. Thirteen-byte animation
filenames fit the real 40/52-byte scratch buffers. Casualty headings fit their
30/10-byte allocations. The nine-byte skeleton/casualty quantity buffers need
at most eight formatted characters; their producers do not locally prove
that bound for arbitrary game-state quantities. No larger allocation is
invented to hide a possible retail limitation.

Other source-specific findings are preserved, not fixed without a proof:

- `ValidHexToStandOn` compares the combat column to **global `MAP_WIDTH-1`**,
  not 12; it accepts sentinel -2 and does not provide full hex bounds.
- `SetCombatDirections` forms the target-army pointer before later validity
  checks. Its caller must have established target identity and wide placement.
  Its real four eight-element arrays seed a 24-sector ring; when there is no
  valid direction it forces a wide-west seed, so ring filling has a seed.
- Mouse direction uses floating division by absolute Y distance. Zero can
  produce infinity/NaN; this is not an integer divide exception. Selection,
  initialized direction map and adjusted wide-unit hexes remain contracts.
- `RightClick` reads side from the argument hex and army index from selected
  hex. Its only in-tree caller passes that selected hex, so no normal mismatch
  is demonstrated by the isolated body.
- `DoLoseWindow` can index player -1 if its initial current-player equality
  accepts -1; later sentinel tests do not guard that first expression. Normal
  reachability is not proven.
- Casualty collection writes at most twenty entries per side; display clamps
  to seven per side within the real 25 widget slots. Artifact transfer is
  bounded by fourteen hero slots within sixteen transfer entries.
- Dynamic army counts must remain at most twenty. Current side/index,
  creature/spell/artifact IDs, standing-animation counts/chance arrays,
  hero sprite/sequence states, finite timer arithmetic and rendering extents
  require their existing lifecycle/data contracts. `AddArmy` searches all
  twenty slots but does not independently range-check the incoming hex.

## Verification boundaries

Before recovery, after restoring each matrix phase, and after the combined
retained changes, native comparison covers all 98 objects / 1826 emitted
function instances and every allocated section with ordered relocations.
The final whole-game build passes 1727/1727 exact functions and
291987/291987 data bytes. These totals do not erase helper-model limitations.

The independent function checker verifies all 36 retail byte bodies and sizes.
Twenty fixed float/double operands pass the narrow supplemental checker; all
other ordinary targets pass except the existing private EH handler and
`__except_list` site-model gaps in seven functions: ShowWinLoseArtifact,
ShowSkeletons, ShowEagleEyeSpell, ShowDeadArmies, DoVictory, DoLoseWindow and
DoSurrender. Their unchanged complete native EH topology is proven, but full
retail relocation closure is **not** claimed for those seven.

The ProcessCombatMsg block reader decodes embedded switch data after its return
as instructions (93/94 blocks); complete byte and ordered jump-target checks
pass. ViewBallista's helper-inclusive view adds four trailing generated blocks
(26/22); its boundary-aware 686-byte and 45/45 ordered-target checks pass.
Neither diagnostic artifact is treated as source control flow.

Evidence remains in `build/command-{owner-before,review-before.obj}`, the
`build-command-{packet,values-restored,retained}.log` build logs, corresponding
all-object comparison logs, all per-RVA `rva/xref/strings/diff/blocks` dossiers,
