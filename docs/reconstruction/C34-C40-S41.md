# C34/C40/S41: sprite conversion and initial hero armies

The clean parent is `b080908d8`. All three complete function bodies,
destination types, sentinels and relevant fixed table/count definitions
were reread. Thirteen written casts are removed without changing native
objects; the unused third army-table column remains after measurement.

## ConvertObject: C40

All six unsigned-byte -1 spellings now use the existing
MAPCELL_SPRITE_NONE255 constant. These are byte sprite indices, not the
separate16-bit MAPCELL_EXTRA_FREE sentinel. Each nonempty-layer check and
chain termination condition remains in place.

All four object/overlay remapping assignments now rely on their actual
u8 destination fields. Integer subtraction/addition still happens before
the conversion, with the same low-byte result. This does not clamp frames,
validate newFirstIndex, or make overflowing integer arithmetic defined.
The coordinate guards still precede raw map access, but inclusive endpoint
arithmetic, map dimensions and valid terminating extra chains remain B58
contracts. The trigger transformation and its flags are unchanged.

## Hero initialization: C34/S41

RandomizeHeroPool's seed assignment loses one cast; the destination is u8
and the actual Random interval is1..255. Its loop visits54 heroes. Class,
skill and CalcMobility invariants remain inherited caller contracts.

SetRandomHeroArmies loses two assignment casts: the selected creature ID
narrows into the existing i8-backed CreatureType storage, and the count
into i16. The six faction rows contain valid named creatures. The two
consumed columns produce counts2..50, including strong-army selection:
the upper Random bound is maximum*10+9, then integer division by10 recovers
at most that maximum. Valid hero/faction indices remain a requirement.

The table's third column is never selected by the two-column loop, but
removing that column changes the native function from834 to642 bytes.
Its real6x3 six-byte records therefore stay. The three-element selected
array is different: selected[2] is read to force selected[1], so it was
not deleted or conflated with the unused table column. All five army slots
are initialized; at most two receive selected stacks.
