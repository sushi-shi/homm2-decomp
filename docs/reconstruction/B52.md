# B52: selected KB text bounds

Pinned genuine-retail pointer tables and private literal destinations prove
these byte bounds, including the terminating NUL:

| Output | Upper bound | Capacity |
| --- | ---: | ---: |
| Morale scratch description | 108 | 200 |
| Complete morale dialog | 540 | 768 |
| Luck scratch description | 156 | 200 |
| Complete luck dialog | 437 | 768 |
| Complete command-line help | 226 | 768 |
| High-score rank / creature name | 20 | 32 |
| Standard congratulations text | 123 | 500 |
| Either campaign congratulations text | 63 | 500 |
| Fixed out-of-memory message | 119 | 768 |

Run `PYTHONPATH=scripts python3 docs/reconstruction/check-kb-text.py` after a
current build. The recorded result is `build/b52-kb-text.log`. It measures raw
CP1251 bytes from the hash-pinned executable, not Unicode comment lengths.
The actual shared `gText` declaration is 768 bytes; the congratulations heap
allocation really is a separate 500-byte owner.

Morale/luck bounds account for the full append chain, not just one string.
Only one initial description and one skill tier can apply. Morale's alignment
alternatives are exclusive, and its all-undead branch exits before the other
appends. The bounds conservatively allow all independently tested event,
artifact and town flags at once, even combinations not simultaneously reachable.
Morale additionally overestimates by allowing some-undead and positive-alignment
text together. Thus these are safe upper bounds, **not claimed reachable maxima**.
The no-modifier fallback is an alternative to modifiers, not another unconditional
append. Table entries that these functions never use are not counted.

The rank's longest creature name is 19 bytes, with no format directives in any
of the 66 names. Changing the first CP1251 byte to uppercase preserves length.
The fixed cheat label is shorter. Congratulations bounds allow every signed
32-bit decimal argument's longest spelling; the `i16`/ordinary gameplay ranges
are no larger. Help resets the buffer and appends exactly fourteen fixed lines;
no command-line argument is included in that output. MemError uses its actual
fixed message and `6400` memory requirement.

Independent whole-function checks pass all bytes, DIR32 sites and ordered
destinations for ShowMoraleInfo (1427 bytes), ShowLuckInfo (830), ShowCongrats
(946), InterpretCommandLine (1523), and MemError (75). Logs are
`build/kb-scalar-0x{6b118,6b6ab,6d109}-retail.log`,
`build/b52-{line,memory}-retail.log`; the signed-cheat-owner update separately
rechecks ShowCongrats in `build/c32-final-retail.log`.

This does not resolve every KB buffer finding. Building descriptions,
player/hero/campaign text, command-line parsing, dynamic dialog labels and
borrowed text ownership still need their individual contracts. The functions
above also require valid source table indices and live objects; arithmetic
fitting an output buffer is not a proof that a corrupt hero, missing palette,
or stale global window is safe. Keep those remaining obligations in the ledger.
