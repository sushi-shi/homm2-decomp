# S01: one aggregate count, not a two-element array

`resourceManager::LoadAggregateHeader` reads two bytes into its scratch object
and consumes only that signed 16-bit count. The unused second array element
is removed: `i16 fpCountBuffer[2]` becomes `i16 fpCountBuffer`; `read` takes
its address and the subsequent assignment uses the scalar. The obsolete
private array-size constant is removed. Allocation logging line numbers stay
unchanged.

The complete four-arm structural/name matrix tested array versus scalar with
both `fpCountBuffer` and `fileCount`. Array and scalar under the existing name
produce the same 312-byte function; both `fileCount` arms remain 99.948456%
fuzzy in the clean state. The latter spelling is not required by the recovered
semantics and is not retained. No generated TU-state input was needed.

Retail and the retained scalar arm agree:

```
retail address / bytes                  candidate offset / bytes
004b89b3 83 ec 14 sub esp,14             +003 83 ec 14
004b8a59 6a 02    push 2                 +0a9 6a 02
004b8a5b 8d 4d f8 lea ecx,[ebp-8]        +0ab 8d 4d f8
004b8a6d e8 de fe 01 00 call _read       +0bd e8 00 00 00 00 ; REL32 _read
004b8a75 0f bf 45 f8 movsx eax,[ebp-8]   +0c5 0f bf 45 f8
```

The frame remains 0x14 bytes. A scalar can occupy the same aligned reservation
without declaring a fictitious extra element. This establishes a sufficient
reconstruction, not the lost original variable name/declaration.

`compare-objects.py build/s01-resmgr-before.obj
build/objdiff/base/BASE/RESMGR.obj` reports all 34 emitted functions identical
and no allocated-section difference, including ordered relocation sites,
types, identities and addends. `check-function.py BASE/RESMGR 0xb89b0` passes
exact bytes, complete DIR32 sites and every one of the 14 ordered target
operands against hash-verified genuine retail. The two private format strings
are checked byte-for-byte at the actual retail operand addresses; unstable
VC6 `$SG` numbers are not treated as source identity. This independently
resolves the generic matrix runner's literal-identity rejection, which also
affected its unchanged baseline.

Reproduce with `PYTHONPATH=scripts python3 docs/reconstruction/` plus the
checker names/arguments above. Logs are `build/s01-{matrix,before-after,
retail-proof}.log`; the reviewed source matrix is preserved in
`docs/matching/LoadAggregateHeader/scalar-count.cpp`. `homm2 build` passes.
The aggregate-capacity guard remains; malformed archive counts and short
reads are separate input-contract concerns, not corrected by inventing
initialization or changing the retail call sequence.
