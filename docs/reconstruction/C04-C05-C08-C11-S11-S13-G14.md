## C04/C05 boundaries retained deliberately

`lpInitWin` is the backend's erased surface publication: five assignments copy
SDK void pointers (two DDAppPaint branches, two DDCreateSurface branches and
WinG's output). Three raster consumers convert that pointer to byte storage.
Changing the global to u8* would move three casts into five SDK assignments;
it is not adopted merely to change a cast count. `_IMAGE::bits` must also
accept WinGCreateBitmap's actual void** output. Only the inappropriate
reinterpretation in Open changes to a normal static conversion.

The palette object and UpdatePalette backends preserve the retail signed-byte
component interpretation. Their arithmetic uses signed loads; raw unsigned
PCX/Smacker/scratch views are explicit character-byte boundaries. Replacing
the whole interface with u8* would require preserving the signed arithmetic
at its consumers and proving all those changes. No unsigned-owner matrix was
run or claimed rejected. Retain the established signed owner and its necessary
byte views; valid component range and input extent remain B23, not facts
established by a cast removal.

BITMAPINFO/LOGPALETTE prefix conversions describe real variable-length SDK
records. DLL result-to-integer success checks and GetProcAddress's function
pointer conversion are real platform boundaries. Their representations are
not retyped by the handle-identity cleanup.
