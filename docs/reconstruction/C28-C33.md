# C28/C33: KB resource types and the numeric dialog payload

Applied six redundant resource-cast removals and one tagged-payload correction:

- `ShutDown`: pass `gPalette`, `bigFont`, `smallFont` directly to `Dispose`.
- `WaitEndSample`: pass `*s` directly.
- `UnloadSystemwideIcons`: pass both icon owners directly.
- `NormalDialog`: write `data.value = IDX(NORMAL_DIALOG_DISABLE_COMMAND)`,
  removing the integer-to-`char*` cast.

The resource declarations establish public, single `resource` bases for
`palette`, `font`, `sample`, and `icon`; `SAMPLE2` is `sample*`.
`resourceManager::Dispose(resource*)` already accepts the implicit conversions.
No owner, signature, layout, null behavior, or lifetime changes.

The dialog's message type is `MESSAGE_WIDGET`, command is
`WIDGET_COMMAND_CLEAR_FLAGS`, and the consumer in `widget::ProcessMessage`
reads `payload.widget.data.value` as a mask. `tag_messageWidgetData` already
has this four-byte integer arm. The pointer arm remains for actual text messages;
the real tagged union is not removed.

NormalDialog's relevant retail and all three source arms are also identical:
`+0x399: c7 85 64 ff ff ff 00 02 00 00` sets message type;
`+0x3a3: c7 85 68 ff ff ff 06 00 00 00` sets command;
`+0x3ad: c7 85 7c ff ff ff 06 00 00 00` stores the numeric mask at
message offset 24. There is no pointer dereference or relocation for this value.

Its independent whole-function checker reports all 5975 ordinary bytes equal
but rejects the DIR32 set and four unresolved EH operands: `+6` targets the
handler at `0x004e8775`; `+c`, `+14`, and `+16a1` refer to `__except_list`.
This is **native-equivalent cleanup, not whole-function retail closure**.
No verifier was relaxed. Detailed logs use `build/kb-clean-0x<RVA>-retail.log`,
with the final IDX dialog check in `build/kb-clean-final-dialog-retail.log`.
The retained dialog also passes a fresh target parse (`c33-final-parse.log`).

`homm2 build` passes (1727/1727 repository function checks), focused relocations
