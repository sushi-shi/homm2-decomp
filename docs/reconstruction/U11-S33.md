# U11/S33: startup buffer and local flag extents

The two player-matching arrays in oldmain now declare six bytes each, matching
their actual accesses. The three unused scalar slots and 256-byte network
buffer are retained after measured alternatives changed retail code.

## U11: the setup record cannot replace the whole reservation

All uses of netBuffer_f were reconciled. The sender initializes a real packed
212-byte OldMainNetSetup and sends exactly that many bytes. It never reads or
sends the remaining 44 bytes of the 256-byte OldMainNetBuffer allocation.

A complete two-arm structural experiment replaces the union local with the
actual setup record, uses its members directly and places the required char
reinterpretation at the existing byte-oriented transmission API boundary.
It introduces no fake padding or auxiliary storage. Both arms compile and
have the same 5329-byte instruction extent, but the smaller record changes the
frame and operand bytes:

| Source | Prologue bytes | Stack reservation |
| --- | --- | ---: |
| Retained 256-byte buffer / retail | `81 ec 74 01 00 00` | 0x174 |
| 212-byte setup record | `81 ec 48 01 00 00` | 0x148 |

The 44-byte reduction contradicts the retail frame. Retain the existing
buffer; this does not claim that a union was necessarily the original source.
No filler member or compiler-state declaration is added to compensate.

The full two-arm product completes in 3.518 seconds. A one-arm diagnostic
replay completes in 2.480 seconds and retains the smaller-record disassembly,
confirming the same text/relocation hashes as its first observation. Both
runs restore source and complete without truncation. Source alternatives are
archived in `docs/matching/oldmain/u11-setup-owner.cpp`; full results are in
`build/source-variant-batch/u11-owner/` and `u11-record-replay/`.

## S33: remove unused array tails, retain measured scalar slots

The full 621-line body and every named access were read. Both matching arrays
are cleared for six bytes. Their ordinary scans use indices 0..5, and the
advancing game-player scan checks its index against six before reading.
Neither array has a read or write of elements 6 or 7. Their declarations now
use OLD_MAIN_PLAYER_COUNT. OLD_MAIN_MATCH_BUFFER_SIZE remains because the
separate global player mapping still uses its eight-byte declaration.

A complete 32-arm product tests the two array reductions independently and
all combinations of deleting three unused scalars. All four array-only
variants preserve text hash `3c6798433424b23b` and normalized relocation hash
`c7839c78c4a9eb48`. Every variant deleting a scalar changes target bytes.
All arms remain 5329 bytes; total size alone would miss those differences.
Trial 3, both arrays minimal and all scalar slots retained, is selected.
The product completes in 39.552 seconds, restores source and is not truncated.
Exact axes are archived in `docs/matching/oldmain/s33-local-storage.cpp`;
results are in `build/source-variant-batch/s33-startup/`.

## Verification and limits

The AST frontend rejects an existing VC6 string-literal conditional in this
function. The reviewed exact-span products therefore use the repository's
documented batch_source_variants runner. Actual VC6 compilation remains the
test; no diagnostic allowance, source workaround or AST/state coverage claim
is introduced. The separate source-dialect check passes in both C++98 and
C++20 and verifies the actual six-byte local array types, retained scalar
sizes and 256-byte buffer. Its VC6 probe proves setup212/buffer256/count6
(`build/u11-s33-layout.log`).

The final build passes 1727/1727 function checks and 291987/291987 data bytes.
Strict native comparison passes all 98 objects and 1826 emitted functions,
including allocated bytes, attributes and complete ordered relocation graphs
(`build/build-u11-s33-final.log`, `build/u11-s33-final-native.log`).
All 5329 ordinary retail bytes remain exact. The general retail checker still
has the same four EH/FS-relative identity gaps, so this is not labeled an
independent complete retail relocation proof (`build/u11-s33-final-retail.log`).
Matrix block diagnostics also retain their existing EH-tail frontier.

G43's startup joins, other functions' S33 findings and B51/B52 mapping,
player-lifecycle, input and text contracts remain separate. No protocol,
startup behavior or malformed-input handling changes.
