# Expansion campaigns: real name owners and byte destinations

All 1,373 source lines, 36 definitions, three private domains, four data
arrays and the complete 153-line parent declaration header were read.
Every function has all ten pattern verdicts. The retained header removes one
obsolete index-offset constant; the packed record is unchanged.

## Applied C78 and O08

C78 removes the puzzle-byte assignment cast and the scroll-byte argument cast
in InitMap. Their destinations already supply the byte conversion. The scroll
expression uses IDX for the actual enum storage domain. Two skill API enum
conversions, two map-domain conversions and the close-command domain remain.
The four-arm product preserves all 1,683 instruction/data bytes. Anonymous
relocation hashes vary with compiler state; the independent final proof checks
actual ordered targets, not hash equality alone.

O08 fixes two genuine out-of-object array expressions. xStableText has four
entries at 0051b7c0; xJosephName has six at 0051b7d0; xUncleIvanName has six at
0051b7e8. The old functions indexed the stable array at map or map+6 when map
is at least four. The valid-map accesses actually select entries 0..3 of the
corresponding name array. Both now name that owner and use map-4, with the
same early-map fallback to name[0]. No overlapping aggregate or artificial
padding array is introduced.

| Function | Old indexed operand | Retained indexed operand | Retail displacement |
| --- | --- | --- | --- |
| JosephName | xStableText + 0 | xJosephName - 16 | 0051b7c0 |
| IvanName | xStableText + 24 | xUncleIvanName - 16 | 0051b7d8 |

Each full function remains 40 bytes. At +1d both emit `8b 04 95` (load through
scale-four EDX); the DIR32 operand is at +20. The native addend changes to
fffffff0 while the symbol changes to the correct six-entry owner. The linked
operand and each valid-map effective address are identical to retail. A
negative COFF displacement is not a source pointer formed before an object:
the source computes the nonnegative index before indexing its real owner.
The complete two-arm products and final ordered-target checks prove this
despite the lower fuzzy score of the correct source in the diagnostic matrix.

No source goto, manual argument-slot varargs, enclosing-owner recovery or fake
stack aggregate occurs. SCampaignChoice is a real five-byte tagged union;
message views follow commands. The opaque four bytes at campaign offset 3f
are not discarded: game save/load write/read all 4f bytes, including this
gap, view map, window pointer and view-only word. The constructor initializes
only the window pointer. Serialized state and short reads are not validated
here, and no smaller semantic save prefix is invented.

## Verification

All 36 complete final retail spans have equal bytes. Thirty-five also pass
every DIR32 site and ordered target. ShowInfo retains its existing private
EH/FS model gaps at +6/+c/+14/+341, with handler VA004e8f61; all ordinary
targets pass. This is not a full TU relocation-closure claim.

Final block comparisons are exact in-range. InitMap and UpdateInfo matrices
sometimes partition embedded switch data as one size-only block, while their
final 84-block views agree completely. IsSpecialLossCondition's helper view
includes four trailing blocks outside its80-byte claim; the seven in-range
blocks and the full byte span agree.

The restored parent passes the strict98-object/1,826-function native census.
The retained census permits exactly the two O08 +20 owner/addend replacements
listed above, then requires equality of every function, allocated section and
ordered relocation in all98 objects. No other difference is waived. Full
build passes1727/1727 function gates and291987/291987 data bytes. Both C++98
and C++20 checks verify actual campaign79/choice5 layout, no source errors and
the same16 external diagnostic identities. Fixed evidence and syntax checks
are included beside this report; all eight experiment source records are
preserved. No core tool changed.
