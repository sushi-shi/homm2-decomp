# Army review: typed animation owners, casts and resource contracts

All47 physical definitions in ARMY.cpp and the IsAlive header body have now
been read. Forty-five source bodies and the inline are newly credited; the
two previously reviewed corpse functions are not counted twice. Both army

incline numerator promotion, and the arguments to atan/sqrt. Its parenthesized
float divisor, floating result precision, coordinate narrowing and integer

existing AFTER_ATTACK/AFTER_MOVE constants.

## C56: repair the unsigned-byte owners

The initial complete256-arm experiment removes seven byte-boolean casts and
one i32 identity cast independently while keeping the old plain-char fields.
It completes in287.530s, without truncation, and restores its source. Only
the original and identity-cast removal match all4567 bytes and128 ordered
relocations. Every byte-boolean removal shortens the function:4560..4566 bytes.
All265-block graphs agree, showing why graph shape alone does not prove code
equivalence. The accepted text/relocation hashes are
`95cdbbcf326e9098` / `aadd2591a1788751`.

The casts expose a better owner model. Every read of `m_animationState` and
`m_animationCycle` is an unsigned-byte truth test. All writes store true/false,
including the sole external write in CastSpell. Neither field is textual.
Both fields now use `u8`; all seven compensating casts are removed. The i32
identity cast is also removed, for eight C56 cast removals in total.

At PowEffect offset+0x1e3, the measured plain-char cast removal has different
instructions, whereas the recovered owner preserves retail:

| Retail and recovered u8 owner | Old char owner with cast removed |
| --- | --- |
| `33 c0` — xor eax,eax | `0f be 02` — movsx eax,byte [edx] |
| `8a 02` — mov al,[edx] | |
| `85 c0` — test eax,eax | `85 c0` — test eax,eax |

The final recovered owner passes4567-byte retail comparison, complete DIR32
sites and all128 ordered targets/addends. The header change passes all98
native objects:1826 emitted function instances, every allocated section and
ordered native relocation/addend remain identical. The original pre-C55 ARMY
object also still matches all48 emitted functions. No global boolean alias,
ABI signature, padding, field position or packed size was changed.

This is a structural follow-up supported by the cast experiment and complete

## B73: proven text bounds, conditional animation bounds

The fixed retail catalogs have66 entries each: singular names at0x4fddc8 have
maximum19 bytes, plural names at0x4fded0 have maximum21. Every source literal
is compared with its exact retail pointer destination and NUL-terminated
payload. The100-byte case-folded target name fits; CP1251 case folding does
not expand it. All reviewed attack/luck formats fit gText768 and local800-byte
snapshots under a deliberately conservative632-byte maximum including NUL.
The12-byte quantity buffer also fits INT_MIN's11 characters plus NUL.
All66 retail five-byte spriteName fields are terminated, with maximum prefix4,
so the fixed sample filename suffixes fit. These are default-catalog proofs,
not validation of arbitrary IDs or modded replacement strings.

SpecialAttack's background Y clamp uses width640, confirmed by matching
ordinary bytes (relative offsets+0xcbb and+0xccd):

```text
81 f9 80 02 00 00    cmp ecx,640       ; bgPosY + bitmap.height
...                 conditional branch
b9 80 02 00 00       mov ecx,640
2b c8                sub ecx,eax      ; 640 - bitmap.height
```

The code has other clipping helpers, so this observation alone is not proof
of an ordinary-game overrun. The bound is not silently changed to443 or480.

BuildTempWalkSeq passes all891 retail bytes/sites/targets. It copies positive
source counts into the16-frame WALK row and16-byte offset array, then adds
the counts without a cumulative capacity check. At+0x5a it forms destination
`frameInfo + 0x175 + count`; at+0x89 it forms offsets destination
`frameInfo + 0x65 + count`. Valid resources must keep each source and the
selected concatenation within16. No larger fabricated owner or extra padding
is introduced to hide subarray crossing. Source count validity and actual
resource reachability remain separate from the byte proof.

Other entries preserve frame/sequence/effect/hex/side/army domains, positive
damage/animation divisors, post-combat resource lifetime and arithmetic
ranges. In particular, AttackTo requires a successful path to have length>=1,
and SetSpellInfluence needs valid nonzero byte durations to keep spellCount
coherent. These are contracts, not automatically classified gameplay bugs.

## B74: the external spell writer

CastSpell has one shared failure-cleanup goto (G66), two unused scalar locals
(S55), real nine-angle missile storage, and remaining narrow conversion
candidates. Its final `m_animationState=false` write is compatible with the
recovered unsigned field, and its entire native object is unchanged.

The16-byte sample filename is initialized only for nonempty sound names.
Retail combat spell IDs0..47 all have nonempty prefixes of at most8 bytes,
giving at most13 bytes with `.82M` and NUL. Creature special IDs101/102 are
mapped to PARALYZE/DISPEL before this lookup. Adventure spell IDs48..64 have
empty names and must not be passed through this combat routine. Hero casting
requires a live current-side hero despite an earlier optional UseSpell guard;
targeted/area/teleport branches likewise require their proper target domains.
No universal input validation or runtime failure is claimed.

Text proof: [check-army-combat-text.py](check-army-combat-text.py),
`build/army-combat-text-final.log`. The existing ViewArmy text checker is
unchanged. Final full build passes1727/1727 function comparisons and
291987 data bytes;877 selftests pass with one skip. Ledger reading coverage
is not a claim that all outstanding findings or the whole project are closed.
