# U10/C26: one real hero patrol record, not boat/patrol aliases

Applied: the hero's three-byte region at offsets `0x29..0x2b` now consists of
`u8 m_patrolX`, `u8 m_patrolY`, and `i8 m_patrolRadius`. The duplicate
boat/patrol union is removed, along with the two AI casts that repaired the
old plain-character Y view. The inactive-anchor sentinel is named
`HERO_PATROL_NONE` (`0xff`); the radius remains signed as its actual reads require.
The packed hero is still250 bytes, with identical serialized field offsets.

All named consumers were inspected:

- `game::SetupOrigData` initializes both anchor bytes to the inactive sentinel.
- `game::ProcessOnMapHeroes` writes map coordinates and radius only when the
  map's hero-extra record has `hasPatrol`. Its castle-entry Y adjustment remains.
- `philAI::DoAI` suppresses movement for an active anchor with zero radius.
- `philAI::DetermineTargetPosition` limits Manhattan distance from the anchor
  and returns the same anchor coordinates when no better target exists.

Nothing uses this region as a boat-record ID. Maps can exceed127 cells, and
both AI coordinate reads already use unsigned-byte semantics. Serialized
prefix/full-object reads and writes remain unchanged. No extra padding, fake
union view, or compiler-state input has been introduced.

Verification:

- Whole native before/after census:98 units,1826 emitted functions, every
  allocated section, ordered relocation identities and addends identical
  (`build/u10-before`, `build/u10-native.log`, `compare-objects.py`).
- Genuine-retail `SetupOrigData`2513 bytes and `ProcessOnMapHeroes`1830 bytes:
  complete bytes, absolute sites and ordered targets pass independently.
- `DoAI`2879 bytes and `DetermineTargetPosition`3430 bytes: all instruction
  bytes, sites and ordinary targets pass. Their only outstanding checker
  names were eleven compiler-generated doubles. [The supplement](check-u10.py)
  validates all eleven native values at their actual retail destinations.
- `homm2 build`, focused relocation checks and all877 selftests pass.

The four retail logs are `build/u10-{init,loader,ai,target}-retail.log`;
the numeric supplement is `build/u10-constant-targets.log`. [The codegen
pattern](../patterns/patrol-coordinate-owner.md) includes the actual loads.
The larger GAME/PHILAI functions remain individually pending for their full
ten-pattern reviews: this focused all-consumer field proof does not claim
those unrelated bodies have been exhaustively reviewed.
