# C25/C32: recover the signed-byte cheat flag owner

Applied: `game::m_cheated` is a `b8` (signed byte) instead of `u8`.
Both `advManager::LoadRemote` and `ShowCongrats` now test the field directly,
removing the casts that compensated for its unsigned declaration. The packed
game size remains `0x660f`, the field remains at `0x639d`, and its save-game
representation remains exactly one byte. It is not changed to C++ `bool`.

The byte evidence distinguishes owner recovery from just deleting a cast.
An initial complete 2/2 ShowCongrats matrix with the **unsigned owner** produced:

| Function offset | Cast / retail | Direct unsigned field |
| --- | --- | --- |
| `+0x1eb` | `0f be 88 9d 63 00 00` — sign-extend byte | `33 c9` then `8a 88 9d 63 00 00` — zero-extend |
| Following test | `85 c9` — test ECX | Same |
| Function size | 946 | 947 |

The unsigned direct version has the same zero/nonzero result for all 256 bit
patterns, but changes a real instruction and shifts following relocations.
Its 99.298250% score (21 exact blocks and one size-only block) is not accepted.
Artifacts: `build/c32-{axes,manifest}.json`, `build/c32-batch/results.json`;
2/2 completed in 4.33 s, no truncation and source restored.

The owner review found only these roles for this field:

- The two truth tests both require signed-byte loads in retail.
- `advManager::Main` and `HandleAppSpecificMenuCommands` set it to 1.
- `game::SetupOrigData` clears it to 0.
- `playerData::Read`/`Write` transfer one raw byte without numeric conversion.
- `AddScoreToHighScore` copies its byte into the plain-character score record.

There is no unsigned comparison, arithmetic use, indexing use, or wider store
in the complete named-consumer census. Byte I/O still preserves every bit pattern,
and both signed and unsigned truth tests have the same zero set. The scalar's
actual flag role and both retail sign extensions justify the signed-byte owner;
this is not a generated declaration or a compiler-state workaround.
LoadRemote's second independent retail load is at function `+0x172`:
`0f be 82 9d 63 00 00` sign-extends `[edx+0x639d]`, followed by `85 c0`.

After that structural header recovery, each consumer independently ran its
complete cast/direct matrix:

| Target | Completed / time | Bytes / relocs | Exact matching blocks |
| --- | --- | --- | --- |
| LoadRemote | 2/2 / 3.91 s | 530 / 55 | 19/19 |
| ShowCongrats | 2/2 / 3.92 s | 946 / 65 | 22/22 |

Both arms in each family have identical complete text hashes, and the direct
arms are retained. These are `build/c{25,32}-owner-{manifest.json,batch/results.json}`;
neither was truncated and both restored source. The ordinary external KB parser
diagnostic is explicitly recorded, as in C28/C33. No target parse error was
suppressed. No TU-state probes were needed.

## Verification scope

The header-only recovery first passed native comparison for **all 98 compiled
units**, every emitted function, every allocated section and complete ordered
relocations/addends (`build/c25-owner-native.log`). After removing both casts,
the same full comparison against the unsigned-owner checkpoint passes again
(`build/c25-final-native.log`). This also checks all writers, serializers,
inlines, class copies and otherwise affected siblings; it is not just a check
of the two edited functions.

Independent genuine-retail checks pass complete bytes, DIR32 sites and ordered
destinations for ShowCongrats (946), playerData::Write (571), playerData::Read
(556), and SetupOrigData (2513). Logs: `build/c32-final-retail.log` and
`build/c25-game-0x{4bff0,4c22b,4df08}-retail.log`.

LoadRemote's checker passes all 530 ordinary bytes and the complete DIR32 set,
but cannot resolve four compiler-private static names: the cheat-warning
read/store at `+0x17f/+0x188` targets `0x00523ffc`; the debug-warning pair at
`+0x1cc/+0x1d5` targets `0x00524000`. The source already explicitly claims those
two local owners. The matrix strict flags for both consumers also reject private
relocation identities; the native comparison resolves their before/after identity,
but this report does **not** call the standalone LoadRemote retail checker a pass
(`build/c25-final-retail.log`). No verifier was relaxed.

The full build passes 1727/1727 repository function checks; 877 selftests pass
(one skipped). Existing loaded-state, serializer bounds and local-static
placement obligations are kept separate from this completed owner/cast recovery.
