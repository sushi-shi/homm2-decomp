# S25: scalar packet checksums

`EncodePacket` and `DecodePacket` used two-element `u16` arrays for the single
checksum written by `calc_crc`. Both now use scalar `u16` objects and pass
their addresses. Every former `[0]` access becomes a scalar access; the unused
second elements and shared private array-size constant are removed. Source
line counts, packet layout, CRC algorithm and transport behavior are unchanged.

The complete four-arm matrix independently selected array versus scalar in
each function. All four compiled in 3.46 seconds. The target EncodePacket
remained 125 bytes with its one-block topology and all ten ordered relocations;
no sibling regression was reported. The final whole-TU native comparison then
checked both changed functions and all other emitted code: all 16 functions
and every allocated section are identical.

Independent hash-verified genuine-retail checks pass both EncodePacket
(RVA `0x8d8bf`, 125 bytes) and DecodePacket (RVA `0x8d93c`, 269 bytes): full
instruction bytes, exact DIR32 sites and all ordered target identities/addends.
This extends the [scalar reservation pattern](../patterns/single-word-count-reservation.md),
not the protocol's bounds: B41 short-packet, sender and payload-length concerns
are unchanged and remain explicit.

Artifacts: `build/s25-{axes,manifest}.json`, `build/s25-batch/results.json`,
`build/s25-before-after.log`, `build/s25-{encode,decode}-retail.log`.
Reproduce native proof with `compare-objects.py build/s25-remote-before.obj
build/objdiff/base/SOURCE/REMOTE.obj`, and retail proof with
`check-function.py SOURCE/REMOTE 0x8d8bf` / `0x8d93c` under
`PYTHONPATH=scripts python3 docs/reconstruction/`.
The source matrix is preserved in `docs/matching/EncodePacket/scalar-checksums.cpp`.
`homm2 build` and all 877 selftests pass.
