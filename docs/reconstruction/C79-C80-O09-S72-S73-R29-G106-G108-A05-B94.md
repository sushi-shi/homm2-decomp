# EVENTS: typed flags, real hero tails and explicit residuals

All 9,078 parent source lines, 43 definitions (42 annotated functions and
ToLowerCp1251), both complete EVENTS headers, private domains, numeric
macros and four packet-view macros were read. Each definition has all ten
pattern verdicts. This is a reconstruction review, not a claim that retail
validates hostile maps or network packets.

## Applied changes

C79 removes 99 written conversions: 67 `static_cast`, 29 HeroEventFlag
constructions and three `const_cast`. This includes 29 flag expressions, whose
inner integer and outer enum conversions are both unnecessary with the
existing typed bit operators; destination-supplied byte/short conversions;
two redundant floating denominator conversions; one redundant inner
necromancy conversion; and two outer character conversions in StrEqNoCase.
The two inner integer conversions in that function remain: the complete
16-arm product does not support deleting them. At least one double operand
is retained in each monster-strength division, so it is not integer division.
The two teleport byte-conversion families also remain after their measured
removals changed code.

C80 changes four map-extra conversions from reinterpret_cast to static_cast:
three in DoEvent and one in DoAIEvent. The actual source is an allocated
`void*`, and the map-object tag selects the recovered event/sign owner. These
are appropriate cast-kind corrections, not four more removed conversions.
The loader allocates the serialized record length; the one-byte trailing
text declarations represent variable-length records, not one-byte allocations.
Record length, terminator and tag validity remain input contracts.

O09 corrects four hero-fragment copies, two sending and two receiving.
The old pointer `&hero.m_spells[52]` named a position inside the 65-byte spell
array but copied 50 bytes: 13 spell bytes and 37 bytes of subsequent members.
The actual serialized owner is the complete 250-byte hero. The retained
pointer is its character representation plus COMBAT_REMOTE_HERO_FIRST_SIZE
(200); the second copy is exactly the remaining 50 bytes. The first copy is
200 bytes. No enclosing-owner recovery, overlapping artificial array or
padding record is introduced. Four necessary whole-object character casts
replace four member-tail expressions. Thus the net source conversion-count
reduction is 95, not 99; the gross C79 removals are still 99.

S72 reduces BarrierEvent's word buffer from16 to the actual input capacity14,
and RiddleStringsEqual's answer buffer from8 to prefix-length+1 (5). The
normal input writes at most13 characters plus NUL; riddle prefix copying
uses four characters and terminates at an index0..4. Both changes are
native-byte-neutral. The three obsolete constants for the old capacities
and spell-array index are removed. These changes recover sufficient source
extents; retail stack reservation does not reveal an unknowable original
declaration length.

## Complete measured alternatives

source alternatives, including grouped sites and extra edits. They completed
766 arms in 764.476063 seconds, with every source restored and no failed
compile or wall-time truncation. The first five use parent3a80a103; the next
52 use that parent plus the measured human flag simplification. The last
two-arm combat-resource product uses the combined retained source and
removes the literal cast to SetPointer's verified const-correct API. They are
independent family products, not a cross-family Cartesian search or a
TU-state census. The combined retained source is verified separately.

measured deletions. This includes DoEvent's unused message, EraseObj's
unused words/stores, EventWindow's eight words (all256 subsets), expansion
and ordinary recruit locals, both generic-site handlers, experience,
skeleton, monster combat, whirlpool, AI handler, PasswordAIEvent, network

axis; that is not a128-arm independent seven-word product. Deleting the
unused sound constant also changes code. The smaller sound name13 and
sphinx input12 declarations fit the checked catalogs/input capacity but
change text, so the 32/52-byte reservations remain.

S73 tests independent creatureCount and combatResult scalars instead of the
ComputerMonsterInteract two-word array. The semantic roles are unrelated;
the proposed scalars keep980 bytes and all41 block shapes but change actual
text (99.811% fuzzy), so the array remains explicit reconstruction debt.

R29 tests a separate sphinx-answer buffer and separate resource/answer
counters. All alternatives change DoEvent's24521-byte text (24620 for the
buffer;24536/24557/24572 for counter subsets). The shared text/resource
buffer and counters remain. Additional DoAIEvent index-role splitting is
UNTRIED, not a measured rejection.

G106 duplicates the mine-claim tail, G107 structures the three guarded
recruitment tails, and G108 duplicates the shrine-learning tail. Their
two-arm comparisons produce24604,24586 and25158 bytes respectively instead
of24521. The original semantic joins remain. Other chest, wagon, artifact,
daemon, teleport, erase, AI purchase and combat joins were read; no untested
rewrite is presented as measured. Artifact gotos can enter a shared tail
inside a switch and then execute another CheckLevel; cloning only its visible
pickup statements would lose that behavior. AI successful joining can
continue into flee/combat; replacing its joins with early returns is wrong.

A05 tests array indexing for the actual flat mine-value allocation instead
of `*(gaiTurnValueOfMine+x+y*MAP_WIDTH)`. It changes11116 to11124 bytes, so
the original address expression remains. It is not itself an out-of-object
access when the map index is valid. Historical experiment filenames use
`a04`/`o08`; the final finding IDs are A05/O09 because earlier IDs already
belong to Overview/expansion campaigns.

## B94: large dispatch and wire contracts

DoEvent's whole switch was read, not sampled by keyword. Important retained
contracts and behavior include:

- Sphinx answerCount is an unchecked byte for eight answers of13 bytes.
  Entry capacity12 fits52, but arbitrary riddle text can overflow gText or
  introduce format directives when subsequently displayed. Seven resource
  additions can overflow before negative clamping. Artifact/name indices
  require serialized-domain validity.
- Resource/campfire type fields can encode values beyond seven resources.
  Witch-hut/shrine/pyramid spell or skill lookup can precede book/capacity
  checks. Several visits use `1 << metadata` without local0..31 validation;
  the TreeKnowledge mask/unsigned shift is separately bounded.
- Boats, mines, obelisks, hero/town interactions and linked map extras require
  valid records. Teleport selection is a two-pass scan of the same map;
  positive destination count and no intervening map change are required.
  Original byte narrowing matters to emitted code and is retained.
- Artifact guard/reward IDs and daemon servant fields can encode values
  beyond actual catalogs. Guarded pickup can execute CheckLevel twice via
  its shared tail. Daemon artifact preflight and later grant call the random
  selection separately; no assumption of the same artifact is introduced.
- Chest/wagon/full-artifact fallback, cleared/erased cells, effect/sample
  ordering, failed-ransom hero loss, and postcombat common UI/endgame paths
  remain retail behavior. Real neighbor arrays and five-army scratch arrays
  are not removed as synthetic stacks.

DoAIEvent is not normalized to the human handler: allied hero interaction
can return before common global restoration; TreeKnowledge uses the
level-to-level delta; shrine/pyramid learning has AI-specific book/wisdom
behavior; guardian power caps at51 in its guardian path; battle-stat indexing
has an upper40 clamp but not a lower clamp; sphinx reward handling uses
Random(0,100)<40; and boat display restoration uses mode3. Resource spending
can be followed by clamping all seven negative balances. Additional source
role/goto alternatives remain untried, not falsely counted as applied.

The complete fixed catalogs prove event text maximum303 including NUL,
recruit-buy322, empty-recruit78, stables208, resources10, colors11,
passwords14, army singular20 and plural22. All30 HouseEvent IDs23..52 have
no directives. Conservative signed-int and actual-name maxima prove the
reviewed monster offer300 and composed global768 formats. These are fixed
catalog proofs only: EventWindow's `sprintf(local,text)` and arbitrary map
text are still unresolved bounds/format regions. A larger caller buffer
cannot make the callee's smaller buffer safe.

RemoteMessage has a nine-byte header and247-byte payload. The producer and
queue consumer establish physical256-byte storage (GetRemoteData copies it
to its268-byte receive buffer), not that packet flags, lengths, tags, sender
or duplicate fragments are valid. Battle155 = header25 + two armies15 +
town100. Hero fragments are201 and51 including their tag. The four existing
packet-view macros remain visible serialization debt: combatRemoteData
contains constructed armyGroup/town types, so a VC6 union of the current
types is not a valid simple substitution. Introducing a fictional padding
array to force a union was not done. Recovering separate POD wire owners is
UNTRIED. The mapHeroExtra patrolRadius/heroClass union is meaningful: GAME
uses heroClass for jail records and patrolRadius for non-jail patrol records.

## Verification and limits

All42 complete final retail spans have equal bytes. All ordinary sites and
ordered targets pass. Ten private floating operands are independently pinned
by exact source offset, DIR32 kind, zero addend, width, value and retail
destination in check-events-evidence.py; private string operands are checked
at every site, including the two separately placed empty strings in
PlayerMonsterInteract. This addresses helper-name differences, not a fuzzy
score waiver.

Four existing private EH/FS model gaps remain: DoEvent, HeroSwap,
ExpansionRecruitEvent and RecruitEvent. Their handler operands at+6 refer to
004e843e/004e8453/004e8468/004e847d; FS references at+c/+14 and respective
epilogues+5ddb/+a5/+a0/+d6 remain unmodeled by the general retail checker.
They are unchanged from the parent but are not declared relocation-closed.

Final block diagnostics classify embedded data after returns in DoEvent,
EraseObj, EventSound, HouseEvent, GiveTakeArtifactStat, DoAIEvent and
GenericSiteAIEvent. RiddleStringsEqual's helper view includes four trailing
constructor/helper blocks beyond its143-byte claim; its seven in-range
blocks and complete byte span agree. Unnormalized private empty-string
names account for the two PlayerMonsterInteract instruction-diff lines.
Full span bytes and independent ordered targets, not helper partition,
are the closure evidence.

Both restored and retained source pass the strict98-native-object census:
1,826 emitted function instances, every allocated section, ordered
relocation identity and owner-relative addend agree, with no allowed
exceptions. The final full build passes1727/1727 function gates and all
291987 data bytes. C++98/C++20 syntax and packed-owner checks verify hero250
with spells at148, army15, town100, battle155, fragment201 and map-event137;
no source errors are introduced and external diagnostic identities agree.
No core matching tool was changed. The evidence scripts and all58 measured
source records are preserved alongside this function-by-function report.
