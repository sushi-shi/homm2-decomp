# Combat-manager reconstruction-pattern review

All38 physical CMBTMGR.cpp definitions, the complete source prolog and trailing
six data owners/vtable, CMBTMGR.h and combatManager.h have been read and
reconciled. The ledger records all ten checklist categories separately for
each body. Shared combatTypes/X_GLOBAL declarations and every changed table
consumer, including the complete Earthquake body, receive follow-up reviews.
This does not credit the unreviewed remainder of KB's large data tail or close
the contracts of every command/drawing consumer of combatManager.

ShootMissile keeps its double denominator: removing the numerator conversion
is byte-neutral, removing the denominator instead shortens1248 bytes to1246.
Its sqrt-result and timer truncations remain; the bitmap API still takes i16.

## B78: verified retail accesses and remaining contracts

- SetupCombat assigns a null battlefield pointer for negative map coordinates,
  then unconditionally reads its terrain word. Retail COFF0x310 zeros the
  pointer,0x31d reloads it,0x325 reads the word and0x32c addresses the terrain
  table. The complete1374-byte comparison and ordered targets agree. Positive
  upper map bounds also rely on callers. EVENTS forwarding callers were
  inspected, but normal-game reachability of negative coordinates is not
  proven. An occupied town also assumes a matching live defender hero.
- SetupAndLoadObstacles calls inclusive SRandom(0,32) for a32-record table.
  Retail at function+0x298 loads32, calls SRandom at+0x29f, scales by14 and
  reads the four-byte mask through+0x2af's operand0x004fbaf0. Index32 therefore
  reads0x004fbcb0, the actual adjacent gEstatesGoldLevel[0], whose retail bytes
  are zero. The JE at+0x2b8 skips the typeUsed stack read at+0x2bf. Thus the
  global one-past read is real, but a default-data typeUsed[32] stack read is
  **not** established. No table enlargement or RNG-bound gameplay fix is made.
- A valid two-cell type at site116 computes hex117. Column rejection sets
  blocked at+0x359, but the following blocked-byte read at+0x36b is unconditional.
  `0x522 + 117*0x62 = 0x31ec`: this exceeds m_hexCells and reads inside the next
  member of combatManager, not outside the entire manager. Subsequent placement
  is rejected; this is not proof of an out-of-array write. The checker verifies
  all32 actual14-byte source/native/retail records, not just declared extents.
- Every default obstacle has one or two cells with offsets0/1. With count
  initialized to zero by InitNonVisualVars and goal at most7, each successful
  placement advances at least one cell, so at most7 icon slots are appended
  within8 slots. Modified catalogs and skipped initialization are not covered.
  Elevation's source25x17 records and indices were read; this does not claim
  a separate complete retail-data comparison of that catalog.
- ShotIsThroughWall first requires opposite InCastle classifications. For
  valid hexes this implies distinct source/target and a nonzero selected
  divisor. InCastle itself is only a classification predicate: it can return1
  for invalid hexes and is not a bounds validator. Extreme arithmetic and
  malformed coordinates remain excluded from the valid-domain argument.
- ShootMissile's final50x50 DrawToBuffer is not the careful/clipped variant;
  endpoints need enough screen margin. Earlier careful save/restore calls do
  not establish this final write's bounds. Squared distance, tick arithmetic,
  positive resource dimensions and nine valid angle entries remain contracts.
- KeepAttack finds a target through this but later accesses gpCombatManager,
  requiring manager identity. The actual attack-stat clamp-20..20 bounds its
  41-entry modifier table. Damage products/sums still require representability.

Other per-body B78 notes cover valid sides/counts, five-slot army-group mapping,

## B79: bounded text, separately from index validity

All19 actual background catalog pointers/strings are checked against retail.
Their longest value is12 bytes,13 including NUL, exactly fitting the member.
None contains a percent directive, so SetupCombat's dynamic sprintf format is
bounded for this catalog. It is not a general guarantee for replacement names.

The two66-entry creature-name catalogs and all ten distinct literal percent
formats in CMBTMGR are inspected. A conservative100-byte bound per text argument,
11 per signed integer and one per character gives at most430 bytes including
NUL in gText[768]. Width02/04 is a minimum width, not a truncation guarantee.
The seven-byte captain name fits hero's13-byte member; Open's13-byte manager
name plus NUL fits baseManager's30 bytes. These proofs do not validate creature,
faction, player or configuration indices used to obtain text.
