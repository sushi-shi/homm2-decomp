# Random objects, score clamping and rumour fallback

Parent: `e6bc8724`. The three complete bodies were reread with their owner
types and retail dossiers. Six written casts are removed; all tested goto
alternatives change native code and are retained only as evidence.

## Per-function findings

`game::ProcessRandomObjects` (`0x5b042`, 1780 bytes) loses five assignment
casts. Its destination owners already supply the conversions: signed 16-bit
artifact coordinates/radius and an unsigned byte monster index. The metadata
source is an unsigned 13-bit field; the random creature range is 0..65.
Coordinates still narrow to 16 bits: removing the explicit syntax does not
validate arbitrary map dimensions. The trigger-code conversion remains a
meaningful typed-domain boundary.

G49 tested three outer structures crossed with two inner structures. Removing
only the final outer goto gives 1770 bytes; replacing the four inner gotos with
switch breaks gives 1742; combining them gives 1732. Grouping the five monster
cases around a bounds-selection switch gives 1794 or 1754 bytes and adds five
relocations. The original nine joins remain. The separate complete 32-arm
cast product has unchanged 1780-byte instruction/data payloads in every arm.
Its raw normalized-relocation hashes differ because `$L` counter names change;
that is not proof of a target change or proof of equivalence. The selected
all-five-removals arm passes the independent full retail target check and the
all-object native comparison, which resolves private labels by section/offset.

`CalcBaseScore` (`0x5efc5`, 375 bytes) retains its three clamp joins. A scoped
`do/while` with breaks gives 374 bytes; nested tier branches give 364. Both
preserve the score arithmetic and shared clamp but change native code.
Floating conversions remain explicit: the four day scales and five tier
operations have actual x87/CRT conversion sequences, including the 1.0 scale.
The caller still owns overflow and valid-day contracts.

`game::SetupNewRumour` (`0x5fdd7`, 1613 bytes) loses the cast on its unsigned
16-bit rumour count: normal integer promotion produces the same signed-int
comparison. The shared-tail alternative moves ultimate-artifact selection
after the statistics-attempt block; successful statistics paths already
return, so exhaustion and non-statistics paths reach the same fallback.
This gives 1601 bytes with or without the count cast. The original goto stays.
The real six-entry stats/order buffers and typed category/record conversions
remain. Event text length, at least two initialized statistics, table indices
and artifact coordinates remain external contracts; the inherited direction
conditions still compare artifact X against both map dimensions.

## Verification

The combined source equals exactly the selected arms. All 98 native objects
are unchanged against the previously verified snapshot: 1826 emitted function
instances, allocated section bytes/attributes and ordered relocation graphs.
The full build reports 1727/1727 exact functions and 291987/291987 data bytes.
The VC6 game layout probe and all 16 C++98/C++20 consumer checks pass.

The full 1780-byte ProcessRandomObjects retail check passes, including its
embedded tables and every ordered destination. Linear disassembly interprets
some jump-table bytes as instructions and displays a misleading difference;
the independent byte/site/target proof does not.

The strict general checker leaves exactly nine private double operands in
CalcBaseScore and twelve in SetupNewRumour. The narrow supplement
[`check-score-rumour-operands.py`](check-score-rumour-operands.py) checks those
exact operand offsets, destinations, zero addends and all eight payload bytes.
It also requires each general check to pass all other bytes, sizes, sites and
targets, with no additional errors. Together these checks establish full
retail equivalence for both bodies without loosening general normalization.

Evidence: `build/game-joins-final-{build,native,dialects}.log`,
`build/game-joins-{monster,score,rumour}-{retail,relocs,blocks}.log`, and
`build/game-joins-private-operands.log`.
