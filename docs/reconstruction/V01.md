# V01: retain the retail vararg exits

`nb_sess` uses the SDK's typed `va_start` / `va_arg` interface; there is no
hand-written stack-slot walker to replace. It does omit `va_end` before its
four return sites. That is portability debt, but adding the missing calls is
not byte-neutral with this target's actual SDK/compiler.

The complete two-arm structural matrix compared the current body with
`va_end(args)` on every exit, including both early-zero returns, the default
return and the common result. All2 arms completed in1.86 seconds. Retail is
1223 bytes; the cleanup arm is1254 bytes (98.106930% fuzzy), with the same31
blocks but five size-only blocks and extra executed stores. The pinned x86
`STDARG.H` defines `va_end(ap)` as assigning a null pointer to `ap`, not a
no-op. The added stores are real code differences; no declaration-state sweep
is justified to erase their required `/Od` effects.

The original source is retained. `check-function.py SOURCE/netwin 0x74372`
now independently proves all1223 bytes, the full DIR32-site list and all83
ordered target operands against hash-verified retail. Eleven operands are the
function's own switch table or case labels. Their addresses are proven from
the function RVA plus their exact COFF-relative offsets, not accepted merely
because their names start with `$L`.

The checker rejects an altered local-label offset and an out-of-section label;
it still rejects the recruitment function's separate-section EH aliases.
Logs: `build/check-function-local-label-tests.log`,
`build/check-function-eh-rejection.log`, `build/v01-retail.log`.
The complete experiment is `build/v01-{axes,manifest}.json` and
`build/v01-batch/results.json`; its source is preserved in
`docs/matching/nb_sess/vararg-cleanup.cpp`. No SDK macro was redefined and no
conditional compatibility shim was added to hide this difference.
