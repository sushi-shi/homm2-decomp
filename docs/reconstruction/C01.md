# C01: read interfaces match the objects they consume

Implemented: `Read13(char*)` and `ReadBlock(void*, u32l)`, with text name
arrays in list/drop widgets declared `char[16]`. Removed 26 written pointer
casts at this boundary. The existing signed scalar conversions, allocation
casts and serialized-structure views are not part of this change.

`Read13` consumes a 13-byte resource name, not signed numeric elements.
`ReadBlock` forwards its destination to CRT `read`; it never interprets an
element. Both source contracts remain the same size/calling convention.

## Native evidence

The unchanged pinned VC6 toolchain artifact verifier passes all 12 files.
Preserved all 98 raw baseline objects before this change under
`build/reconstruction-baseline`; rebuilt 38 affected units with `ninja base`.
Run from the worktree in the build shell:

```
python3 docs/reconstruction/compare-c01.py --isolated-c01
```

Result: 1,826 emitted function symbols, zero instruction-byte differences,
zero ordered-relocation differences; zero allocated-section differences.
This compares against the pre-change source, **not** a claim that all 1,826
functions match retail. The script also compares allocated exception/data
sections, including their bytes and complete relocation graphs.
The isolation option uses the preserved pre-O01 Miles object and pre-O02
SEARCH object; those later ownership changes have separate explicit field-map
proofs. All other units use current objects. Without the option the report
also exposes those later, intentional ownership differences.

Only two interface symbol renames are authorized. Repository normalization
handles anonymous literals. `$L` labels and `$anon_data_` relocation targets
are identified by exact section ordinal and offset, not discarded: those
sections and their outgoing relocations are compared too. VC6 changed private
EH label numbers when the signatures changed; no EH payload changed.
