# U15: adjacent town spell counts

The town record now has a20-byte flat/2D spell union followed by five real count
bytes. The unused19-byte overlay prefix and the sixth count element that aliased
the last spell byte are removed. Total record size and every subsequent field
offset remain unchanged.

| Consumer | Previous count index | Retained zero-based index |
| --- | --- | --- |
| town::GiveSpells | stage+1 | stage |
| town::BuildBuilding | buildState; level+1 | buildState−1; level |
| townManager::SetupMage | level_f+1 | level_f |
| MageGuildHandler | level_d+1 | level_d |
| game::SetupTowns | slot12 | slot12−1 |
| philAI::HeroInteractionAtTown | castLvl | castLvl−1 |

All six complete consumer bodies were read; the last was newly reviewed in
this change. A full source/header search found no count0 or prefix consumer.
The flat spell view remains because SetupTowns actually uses it. No before-array
pointer, biased accessor, fake padding or replacement union was added.

This was one evidence-backed structural layout recovery, compared to the clean
parent `77db5b7fe`, not a spelling permutation or TU-state search. Each count
access maps to exactly the same byte. For example, the zero-based readers
already use town+index+0x50; one-based readers/writers use town+level+0x4f.
Moving the count owner to0x50 and subtracting one from a one-based index keeps
that address. Both forms of byte access are present in the retail code.

`build/build-u15-control.log` and `build/build-u15-adjacent.log` pass the complete
build. The clean object tree is `build/u15-before-objects`.
`build/u15-all-native-layout.log` compares all98 before/after objects using
`compare-objects.py`'s canonical native census: all1826 emitted function
instances, all allocated sections and complete ordered relocations/addends
agree. This includes all26 rebuilt TUs, not just the four edited consumers.

wrapper with SOURCE/TOWN flags, checks size100, spell offset0x3c/extent20,

It is not linked or included in reconstructed source.
