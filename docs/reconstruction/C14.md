# C14: retain recruitment resource-name boundary casts

Final disposition: both casts are restored. The experiment below proved native
VC6 equivalence, but the full annotation regeneration exposed a second required
dialect: C++98 with `H2_CONST` empty. In that dialect a conditional expression
between string literals has type `const char*`; it cannot use the deprecated
single-literal conversion to the constructor's `char*` argument. Both calls fail
annotation recovery without their explicit casts. The modern interface remains
const-correct. No parser exception or ABI change is added to permit this cleanup.
The following records the measured, now rejected, cast-removal experiment.

`check-resource-name-dialects.py` verifies both retained and removed forms in
both dialects: retained forms have zero unreviewed project errors; removed
forms have exactly two C++98 errors and zero C++20 errors. Full annotation
regeneration and build then pass. The final98-object native comparison in
`build/c02-final-native.log` also proves restoring both casts is byte-neutral.

Removed two `const_cast<char*>` expressions around conditional resource names
in `recruitUnit::Open` and `QuickViewRecruit`. The existing `heroWindow`
constructor accepts `H2_CONST char*`: this already models a read-only name for
the modern compiler while preserving the retail compiler's ABI. No owner,
signature, allocation, resource selection or source line count changes.

The complete four-arm matrix independently selected cast versus direct
expression at each site. All four arms compiled in 2.83 seconds with identical
19-block Open topology and 619-byte size. The runner reports 99.954025% even
for its unchanged baseline, with 30 versus 27 relocations; this is not evidence
against the cast removal. Both functions contain compiler-emitted construction
cleanup, despite this TU's base_nogf profile.

The stronger **native before/after** test compares all 11 emitted functions and
every allocated section, including `.text$x` handlers and `.xdata$x` unwind
metadata. Bytes, ordered relocation sites/types/owners/addends and section
attributes are identical. This proves the source cleanup preserves the whole
compiled TU, including its exception machinery. It does not independently
certify that every baseline owner claim matches retail.

The scoped genuine-retail check confirms all non-relocation instruction bytes
for Open (619 bytes, RVA `0x8c522`) and QuickViewRecruit (353 bytes, RVA
`0x8ceaa`), and every ordinary call/data/string target. Its remaining failures
are specifically compiler EH operands: the handler at function offset 6
(`$L58231` / `$L58252`, retail VA `0x004e8abb` / `0x004e8ad0`) and three
`__except_list` operands per function. The latter are FS-relative zero slots,
not image addresses or missing PE DIR32 sites. The existing comparison
normalizer recognizes these two classes; the narrower reconstruction checker
does not. No unknown-owner acceptance was added to make that checker pass.
The full native graph equivalence is evidence for the native experiment;
an independent recursive retail EH-graph certificate remains a checker limit.
