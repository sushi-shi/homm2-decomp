## B63: destination capacity proof

Assume nonnegative file sizes, successful storage and arithmetic within i32;
in particular, max(oldSize,joinSize)+5000 must not overflow. A length header
uses at most three bytes. Every nonterminal literal-copy header is followed
by a skipped matching run of at least four bytes. Such a run saves at least
three bytes after its own header: lengths 4..31 cost one header byte,
32..8191 cost two, and larger lengths cost three. Its savings pay for the
preceding literal-copy header, if any.

At termination, the existing encoder advances position to oldSize, because
its terminal length is oldSize-position. Only that final copy header is
unpaired. Hence differential output is at most oldSize+2+3. Full-send output
is joinSize+2. Both fit the existing max(oldSize,joinSize)+5000 allocation.
Output positions grow monotonically, so this also bounds intermediate writes.
The +5 bound is tight for an 8192-byte all-different pair.

This destination proof does **not** establish readable input or correct join
content. The inherited terminal copy can overread a shorter new allocation
or omit a longer new tail; [B63](B62-B63.md) remains a real defect. No length
correction or allocation-size change is applied.

`check-diff-bounds.py` checks the source constants/control fragments and a
source-derived model over 261121 binary old/new pairs through length 8, plus
byte/word thresholds. This is a model check, not execution of the game.
It also checks both command values and every length 0..700000 through the
modeled header encoder/decoder. The existing 0x2f0000 mask loses bit 20:
length 0x100000 encodes a length that decodes as 0. No mask repair is made.
Received header availability, position bounds, command domains and the
decoder's 700000-byte output limit remain separate contracts.
