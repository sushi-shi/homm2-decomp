# C36/S37/S38/R08: map input and event coordinates

This follow-up starts at clean `d7da2d15c`. Both complete bodies were
reread: LoadMap (`0x53b9e`) and RandomizeEvents (`0x513cf`), including all
switch arms and three map sweeps. Their actual game/town/event field types,
local buffer consumers and narrowing boundaries were reconciled before
testing. No shared header or file format changes.

## Applied changes

LoadMap now reads coordinates into u8 x[1] and y[1], removing six
compensating u8 casts. All successful one-byte reads still produce the
same coordinate bits. The old-format x/y assignments of-1 still produce
255; this is the same off-map sentinel tested by the existing guard.
The town/mine coordinate fields are already u8.

The record-type array becomes i8[8], not unsigned: its negative test uses
the high bit as the castle flag, while the lower seven bits select faction.
The mine-type conversion likewise retains the original signed value. The
type array and ignored trailer array retain their eight-byte extents after
the smaller alternatives change native bytes. Their actual direct reads
are one byte and two bytes, respectively. Two enum-domain casts and the
two erased-allocation casts remain real boundaries, not failed removals.

RandomizeEvents loses seven assignment casts: two event coordinates, four
boat-coordinate assignments and the abandoned-mine guardian count. Event
coordinates are u16 and boat coordinates are u8; the old intermediate
signed i16/i8 casts do not change the stored low bits on the measured ABI.
The guardian count remains u8 and its actual Random bounds are30..60.
Ordinary map-coordinate validity is still a caller contract; none of these
changes introduces coordinate validation or changes the clamping behavior
of the adventure accessor versus the raw fullMap accessor.

## Domain and native verification

`check-loadmap-domains.py` compiles the independent byte-domain probe with
VC6, proving signed plain char/i8, the unsigned255 sentinel and exact
unsigned destination pointer types. It checks all256 raw byte values for
coordinate/sentinel/high-bit/masked-type equivalence. Clang checks the
entire GAME source in both supported dialects, including the actual local
element types and retained1/1/8/8-byte extents. It does not assume file reads
succeed or claim a bound on arbitrary input dimensions.

The full build passes1727/1727 function gates and291987/291987 data bytes.
All98 native objects,1826 emitted function instances, allocated bytes,
section attributes and ordered relocation graphs are unchanged, with no
exceptions. The existing VC6 game-layout and16 consumer/dialect checks pass.
Both functions independently pass complete ordinary-retail bytes, sizes,
DIR32 sites and ordered target identities, with no checker gaps.

A raw before/after relocation audit finds70 changed compiler-private names
among RandomizeEvents'178 sites and one among LoadMap's45 sites. Every
changed name retains its exact section/offset and relocation site/type;
LoadMap's changed name is the same path-format string. The full independent
retail checks verify those destinations, including the local switch targets.

Evidence is `build/build-c36-final.log`, `build/c36-final-native.log`,
`build/c36-domains.log`, `build/c36-final-dialects.log`, and
`build/c36-<RVA>-final-{retail,relocs,blocks}.log`. The clean snapshot is
`build/c36-loadmap-before`, checked by `build/check-c36-native.py`; the
