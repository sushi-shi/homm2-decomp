## Retained structural changes

A01 makes actual owners visible without inventing raw offsets. SetArmyCommand
already dereferences the strip before its pointer comparison. MageGuildHandler's
three accepted control ranges constrain its level to0..4; the existing
one-based count access remains1..5. This spelling change does not resolve the
separate U15 count-owner layout question.

BuyBuild visits seven resources and packs all positive-cost entries at the
front of both arrays. Every following scan stops at seven; the two displayed
rows have at most four entries each, and the shared output cursor never exceeds
the compact entry count. Both independent extent changes and their combination
were tested. The now-unused private `BUILD_RESOURCE_STORAGE_COUNT` enumerator
was removed with the final source cleanup.

SetupWell initializes and consumes exactly six dwelling choices. Its values
are0..11, which index the town's twelve garrison/dwelling entries; this does not
mean every faction supports every possible corrupted building bitmask.

SetupThievesGuild, GetCategoryStats and SortStats all use the actual player
count, at most six under the game contract. The companion stats array already
has six entries. The rank traversal additionally requires consistent live/dead
counts and initialized statistics; increasing only the order buffer never made
invalid player state safe. Its now-unused public eight-entry constant remains
non-emitted header metadata, not a padding object.

The four arrays lose seven declared bytes in total. VC6 still aligns their
reservations as before; no artificial padding or steering code was introduced.
Identical machine code does not establish the original declaration extents.

## Why the boolean conversion remains

Both expressions produce0 or1, but the current VC6 parent distinguishes their
intermediate types. The retained source and retail have, at function+0x120:

```asm
0f 9d c0       setge al
0f bf c8       movsx ecx, ax       ; +0x123
89 4d e4       mov [ebp-0x1c], ecx
```

The removed-cast arm records `89 45 e4` at+0x123 instead. It is three bytes
shorter, changes relative branches/relocation sites, and has25 exact diagnostic
blocks plus one size-only block rather than26 exact blocks. Its score is
96.652540%, not closure. This rejects the tested cast removal in this parent;
it does not identify which original source construct caused the16-bit path.

same bytes and relocation graph; no verifier was weakened to accept EH state.

function ledger. Reading a function is not a claim that all its findings closed.
