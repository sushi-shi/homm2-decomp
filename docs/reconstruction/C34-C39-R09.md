# C34/C39/R09: weekly casts and counter roles

The clean parent is `bef26afa0`. PerWeek, PerDay and CheckHeroConsistency
were reread in full. Two casts are removed from PerWeek; the tested
role-separation alternatives change native code and are not retained.
No unused local was found in PerWeek itself.

## PerWeek conversions and domains

The replacement hero ID now assigns naturally into the existing i8
available-hero field. GetNewHeroId's positive retry loop chooses an ID
from 0..53 before returning, so the explicit narrowing is unnecessary.
The monster-growth comparison now uses its already-i32 remainder directly.
The faction conversion and three floating-to-i32 growth conversions stay:
they express enum construction and truncation of scaled growth.

The monster metadata owner is an unsigned 13-bit field: count mask 0xfff
and guard bit 0x1000. `check-weekly-operands.py` checks all 8192 metadata
values and all 7 random rolls. The remainder stays 0..6, the guard is
preserved, and the final count is at most 4000 within the field. The clamp
is existing retail behavior, not a new gameplay change.

Dwelling indices 19..30 map to the 12 garrison entries; fixed town and hero
loops fit 72 and 54 records. Faction/owner validity, map dimensions and all
six player mappings remain B61 contracts. In particular, the available-hero
loop uses GAME_PLAYER_COUNT rather than m_playerCount, so an unused player
with color-1 can reach the color-map lookup. No new guard is inserted.

## Counter-role alternatives

PerWeek's outerIndex starts as a random roll and later traverses towns,
players and heroes. Four structural families were compiled: unchanged;
only the roll moved to a scoped weekRoll; separate function-level locals
for all four roles; and separate locals within the roll/loop scopes.
Each family is crossed with both independent cast choices, for 16 arms.
The scoped-roll family grows 6824 to 6833 bytes and frame 0x1ac to 0x1b0.
Both full role splits grow to 6851 bytes and frame 0x1b8, with distinct
stack-access sequences. The original role reuse remains.

PerDay keeps its actual player counter but tests separate mine, town and
hero counters, either at function scope or inside each relevant loop.
Its three-arm product retains2576 bytes in each case but grows the frame
from 0x38 to 0x44 or0x4c and changes live stack operands. The scoped version
has separate locals for repeated hero/town phases, rather than carrying
their values between unrelated loops.

CheckHeroConsistency similarly tests separate hero/town counters while
retaining the actual player counter. Both alternatives keep 1225 bytes but
grow the frame from 0x28 to 0x30 and change operands. Existing sane/loop
retention from S42 is not disturbed. All these counter splits are retained
as measured negative alternatives, not applied edits or proof that every
future source shape is impossible.
