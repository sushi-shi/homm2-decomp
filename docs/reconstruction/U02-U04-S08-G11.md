# U02–U04: separate path storage and single queue/target fields

The pathfinding record now contains its grid-pointer union followed by one
actual256-byte direction array. The old3-byte/4-byte padding prefixes and
overlapping257/256-byte path views are removed. Queue count/maximum and target
coordinates have single fields instead of duplicate aliases. Two redundant
unsigned comparison casts are also removed. No bytes of the real owner are
deleted, and no cast, biased pointer or replacement padding is introduced.

## Storage and access mapping

searchStorage remains260 bytes: the two legitimate grid-pointer views share
offset0, and directions begins at4. searchArray remains0x2518 bytes, with
queue count0, maximum4, path length8, target X12/Y16, queue20 and storage0x2414.
Thus the actual direction owner begins at searchArray+0x2418.

| Previous access | Actual direction index |
| --- | --- |
| aiPath.directions[i] | i |
| path.directions[i+1] | i |
| path.directions[1] | 0 |
| ShowRoute's path.directions[index] | index-1, only in its index!=0 branch |

All15 old path-view accesses across ten functions were reconciled, including
both producers, the AI's direction overwrite, and the route renderer's guarded
previous-direction lookup. No consumer reads old path.directions[0], which
overlapped the last pointer byte. BuildPath writes at most256 directions and
then clears its length on that limit; combat-path construction retains its
existing256-entry stop. Consumer path-length/direction validity remains an
input/lifecycle contract, not a new bounds check.

The cells/nodes pointer views and searchNode's signed/unsigned tagged fields
remain. These serve existing grid APIs; their presence is not claimed to prove
portable union/object lifetime. Separating the live pointer from its adjacent
direction array removes the artificial whole-storage overlap.

U03 keeps the already-used u32 queue count and maximum. SeedPosition's pop,
indexed read and conditional put-back use that same count; the old signed
queueSize alias and unused queueCursor name are gone. The count's successful
pushes stop at1024 and pops are guarded by count>0. U04 preserves the exact
target-word mapping and reset order: old lastX becomes specialTargetY, then
old lastY becomes specialTargetX. No coordinate order is silently swapped.

## Complete source products

The owner recovery is structural, against e9d0dc9e. Four follow-up products
completed ten arms without truncation and restored source. Exact axes and
all results are archived under `docs/matching/search-owners/`.

- G11 structured do/while completion:1315→1312 bytes and73→68 blocks; retain
  the existing shared moat-restoration gotos. The alternative preserves API
  work and failure/success results but does not reproduce native code.

  deletion changes frame operands. Keep both slots; matching size/CFG alone

- U03 combat comparison: both406-byte arms and graphs match; remove explicit
  u32 conversion of middle_a. The right operand's unsigned type already
  performs the same usual arithmetic conversion.
