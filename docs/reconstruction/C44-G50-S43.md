# Save transfer: C44, G50, S43 and the U14 protocol boundary

Parent: `68ed2e25a`. Both complete transfer bodies, their protocol and text
declarations, the complete `advManager::CheckHandleNet` consumer and all three
transmit call sites were reread. This change removes 24 redundant casts and
corrects the name of the fourth initialization word. It does not yet replace
the raw packet owners or change the network API.

## Applied conversions and recovered meaning

`TransmitSaveGame` loses nine literal `const_cast`s and two explicit i16
conversions directly at packet-index assignments. `ReceiveSaveGame` loses
thirteen literal casts. LogStr, LogInt, AiPrint, BVResMsg and NormalDialog
already accept text through H2_CONST: the existing historical ABI is retained,
while the modern dialect accepts the literals as const text. No callee or
interface changes are needed.

Both index destinations remain i16; their assignments still narrow. Under
the tracking-array contract, packet indices lie in 0..4999 and fit, but the
functions do not enforce that contract. These edits neither widen the wire
format nor validate malformed input.

The fourth initialization word is an exit flag, not a player number.
`NextPlayer` and the initial oldmain transfer pass 0; `HandleRemoteDeadPlayerExit`
passes 1. CheckHandleNet reads this word as `savePlayerExited` and conditionally
reports the sender's exit after receiving the save. The parameter is now
`playerExited`, and the index constant is `REMOTE_SAVE_HEADER_PLAYER_EXITED`.
The field and parameter remain i32, with the raw supplied value unchanged.

## G50 and S43: measured forms retained

The sender's guard alternative replaces the failed-open cleanup goto with
`if (file != -1)` around the transfer, leaving FileError and cleanup order
unchanged. This loses eight bytes (1971 to 1963). The retail block view has
a separate jump block behind the return path which jumps back to cleanup;
the original source reproduces it. No dummy control flow is introduced.

The sender has five unread scalar declarations, not six: unused1d0,
unused208, unused21c, unused8 and unused9. Each individual deletion retains
the 1971-byte size but changes instruction bytes. The latter three share
the same changed text hash; unused208 and unused1d0 give different hashes.
The full 128-arm product of these five deletions, the guard alternative and
oldTrack initialization deletion has only one baseline-identical arm: the
original. Equal size is not equivalence.

A separate complete 32-arm sender family tests all omission subsets of the
initial header, fileData, result, acknowledged and oldTrack assignments.
Each individual omission loses ten bytes; every nonbaseline subset differs.
The reply initialization is meaningful because TransmitAndWait has paths
which do not write the response. The transmitData null value supports
failed-open cleanup when regular compression is disabled; success starts
false for that failure path. These are not deletion candidates.

The receiver's 16-arm family tests unused2080 (declaration plus zero store)
and the initial file, packet and oldTrack assignments. Its separate 32-arm
family tests all omission subsets of the initial ackBuffer, incomingData,
decodedData, received and success assignments. Every individual deletion
loses ten bytes (1736 to 1726), and every tested nonbaseline subset differs.
The finished initialization is read by the loop and remains meaningful.

These are complete independent family products, not a joint product of
every axis across the two functions. They establish measured negatives for
this source parent, not impossibility under a future structural recovery.
No AST variants, TU-state census, generated padding or steering are retained.

## U14 and B62: what remains open

The 256-byte sender allocation genuinely changes protocol form: four i32
initialization words, then an i16 packet index followed by up to 200 bytes,
then an i16 acknowledgement-request index. The allocation is not a fake
stack aggregate. A shared typed protocol owner remains a candidate, together
with AdventureRemotePayload's variable-length byte view and the char/u8
network/codec interfaces. No new union or cast-hiding wrapper is added here.

Each filename buffer has 452 bytes. A terminated configuration filename
within its 13-byte field needs at most 19 bytes with the six-character
`.\DATA\` prefix and NUL. ReadPrefs generates these names from a four-byte
uniqueSystemID field; the 19-byte claim still depends on proper termination
and valid configuration storage, not on a local bounded formatter.

Other contracts remain: nonnegative sizes and safe allocation arithmetic,
successful complete file reads, allocation success, codec output capacities,
packet indices within the 5000-byte tracking arrays, complete two-byte
prefixes, valid payload lengths and reply sizes, and decoded output within
700000 bytes. The receive loop does not locally bind packets to the expected
sender. CRC values are logged but never compared to the expected values.

The receiver still initializes only 100 bytes of its 256-byte acknowledgement
buffer and transmits 200. [B62/B63](B62-B63.md) records this inherited defect;
no zero-fill or length correction is silently applied. The existing
alias-aware cleanup of compressed/uncompressed buffers is preserved.
