# Town setup, army commands and dialog handlers

Parent: `7d4ffd56`. Ten complete function bodies were reread. Eight written
casts are removed across four functions. Twenty-nine unused locals/results, the
army-swap temporary's two roles, two crest casts and the split handler's
three joins remain after measured alternatives change native code.

## Applied conversions

- `townObject::townObject`: remove the explicit widget-ID cast. The border
  constructor already takes a signed 16-bit argument. The actual conversion
  remains; the written cast adds no meaning or native instructions.
- `townManager::RecruitHero`: remove four assignment casts. Hero owner,
  available-hero flags and available-hero IDs already have signed byte owners.
  The real faction-domain conversion remains. This does not validate hero IDs,
  player indices, available slots or the result of GetNewHeroId.
- `TavernHandler`: remove the timer-assignment cast. KBTickCount returns i32l
  (signed 32-bit long in this target), and glTimers holds signed 32-bit i32.
  The wrapper still returns GetTickCount's bits through its existing signed
  return type. Signed addition, tick wrap and frame-counter overflow are not
  hardened by removing the cast.
- `townManager::SetupWell`: remove two byte-assignment casts. The six loop
  indices and upgrade choices yield dwelling indices 0..11. The real unsigned
  CP1251 character comparisons/conversions remain, as do the six-byte owner,
  text buffers and actual monster record.

The constructor and recruitment matrices preserve instruction/data payloads
but rename compiler-private labels, so their raw relocation signatures differ.
The selected arms are accepted only after the full native comparison resolves
those labels by section/offset. Unselected arms do not inherit that stronger
proof merely because their masked bytes agree.

## Verification and limits

The combined source equals exactly the selected arms and removes eight casts.
All 98 native objects are unchanged against the fresh parent snapshot:
1826 emitted function instances, all allocated section bytes/attributes and
ordered relocation graphs. The full build reports 1727/1727 exact functions
and 291987/291987 data bytes.

[`check-town-handler-types.py`](check-town-handler-types.py) compiles the
owner/type probe with VC6, then checks the entire TOWNMGR source plus that probe
in C++98 and C++20. Actual byte/count/timer reference types, signed int/long/tick
widths and the army size pass. These probe declarations are never linked into
the game.

The strict retail checker passes all bytes, sizes, DIR32 sites and ordered
targets for DoCommand (1176), MageGuildHandler (340), TavernHandler (288),
SplitArmyHandler (719) and SetupWell (1607).

The constructor (397), SetupTown (2527), SplitArmy (886), RecruitHero (1803)
and DoTavern (299) retain their baseline private-handler and FS exception-list
model gaps: four reported operands per body and the corresponding site-list
disagreement. Ordinary bytes, sizes and other targets agree. The before/after
records preserve the same operand offsets and retail destinations; only private
counter names change. These five are **not** claimed as complete strict retail
closures, and no general checker or manifest was relaxed.
