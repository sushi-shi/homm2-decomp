# U07/S24: byte receive buffers and nine thread events

Removed the unused NetbiosPayload word view. The owner is now a struct with
one 4096-byte byte array, matching every actual receive/prefix/copy consumer.
The seven-element receive allocation remains 28672 bytes. No typed word load,
word store, escaping word pointer or second interpretation was found.

NetbiosThreadEvents now contains exactly nine handles (36 bytes), not ten.
The initialization clears 36 bytes, the create/close loops visit 0..8, and
WaitForMultipleObjects receives nine. Sending signals handle 0; receive polling
visits 2..6, while arming a valid session 0..6 selects session+2 (2..8).
There is no consumer of handle 9. The unused storage-count constant is removed;
the ABI control block and its reserved bytes remain unchanged.

## Allocation and language evidence

The compile-only `netbios-layout-probe.cpp` proves payload size 4096, seven payloads
28672, events size 36, exactly nine handles, payload member offset 0 and NCB size 64 under
the actual VC6 compiler. `check-netbios-layout.py` additionally checks the whole
netwin TU with the same assertions in both supported C++ dialects. All pass
in `build/u07-layout.log`.

Native COFF retains section 4's event owner at offset 0x8, receive queue at 0x30
and receive payloads at 0x48. The new event object ends at 0x2c; the compiler
supplies the four alignment bytes before the next owner. At retail placement
that is events at 0x528658, padding 0x52867c..0x52867f, queue at 0x528680 and
payloads at 0x528698. Padding is not a tenth handle or a replacement source
symbol. No alignment attribute, filler member or alias was introduced.
