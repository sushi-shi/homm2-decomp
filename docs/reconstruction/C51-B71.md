## B71: confirmed retail sequences

TurnValueOfObelisk (`0x8584e`) sign-extends the game's artifact byte and reads
its value before checking the NONE sentinel:

```text
+0x27  movsx ecx, byte [game+0x6397]
+0x2e  mov edx, [gArtifactBaseRV+4*ecx]
...    divide local artifact value by110
+0x66  movsx eax, byte [game+0x6397]
+0x6d  cmp eax, -1
```

The owner field is signed i8 and ARTIFACT_NONE is -1. That input therefore
reads four bytes before the value table before taking the zero-return branch.
This is preserved, not disguised with a leading table element or a moved
guard. A separate nonzero obelisk-count contract applies on the non-NONE path.
Ordinary gameplay reachability of the sentinel is not established here.

HeroInteractionAtHero (`0x86b43`) saves the recipient pointer but never uses
the saved value in its conditional role-change sequence:

```text
+0x1ca  mov ecx, [ebp-0x2c]   ; recipient
+0x1cd  mov [ebp-0x40], ecx   ; saved, subsequently unread
+0x1d0  mov edx, [ebp-0x10]   ; dominant
+0x1d3  mov [ebp-0x2c], edx   ; recipient = dominant
+0x1d6  mov eax, [ebp-0x2c]
+0x1d9  mov [ebp-0x10], eax   ; dominant = recipient
```

Both roles end up with the same pointer. The full909 ordinary bytes, complete
DIR32 sites, other ordered targets and the supplement's four fixed private
doubles agree with retail. This is not repaired into a swap. The branch is
evaluation-only, so the source evidence does not establish an actual troop
self-transfer; it does change which armies are used in that evaluation.

EvaluateOneTimeCreaturePurchase (`0x86369`) passes all405 bytes and complete
sites/targets independently. Its replacement-value expression indexes the
monster database by army slot, not the creature stored in that slot:

```text
+0xda  movsx edx, word [hero+2*slot+0x6a]  ; quantity
+0xe5  imul edx, [gMonsterDatabase+26*slot+2]
```

The preceding code multiplies the slot itself by26, the database record size.
The index is within the database for slots0..4, so this is a semantic-value
issue rather than an out-of-bounds access. No reconstruction-only correction
is justified by these matching bytes.

Evidence: `build/ai3-<rva>-{rva,xref,strings,diff,blocks,asm,retail}.log`,
`ai3-value-constants-final.log`, `ai3-native-final.log`, and the final C51
retail/relocation reports.

## Remaining contracts and source-shape findings

The per-function B71 entries distinguish real seven-resource vectors,
two-hero values and spell-score storage from fabricated aggregates. In
FightValueOfStack, positive spell scores and the selection-count guard ensure
the selected maximum index is assigned before use. Other contracts remain:
valid map/hero/town/skill/artifact domains, nonzero strength/resource ratios,
representable troop/cost arithmetic and terminated debug text. A 100-byte
debug buffer with `%15s` is not proven safe merely by the format width.

QuickCombat requires an attacker hero despite some earlier null checks, and
its defender-win callback targets and final win callbacks are retained source
behavior, not silently corrected. BuildHero appends to the eight-entry list
and indexes the replacement hero ID without a local failure guard; callers
must establish capacity and valid IDs. Source inspection alone does not prove
a normally reachable crash in these paths.

C52 covers narrow cache/turn/hero/coordinate/count conversions and typed loop
roles. R14 records army/spell/skill/artifact/resource index reuse. S52 records
unread scratch, unconsumed scalar outputs and the saved hero pointer above.
These remain untried rather than presented as applied changes. No gotos or
manual argument-slot varargs were found in this batch.
