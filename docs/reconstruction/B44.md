# B44: release the visibility-map array as an array

Applied in `advManager::Close`: `delete[] m_visibilityMap` now corresponds to
`Open`'s `new u16[MAP_WIDTH * MAP_HEIGHT]`. The pointed-to owner is an array
of trivial two-byte elements. No storage size, field offset or runtime
allocator call changes.

The complete two-arm source matrix compares scalar and array deletion in the
same clean TU state (`build/b44-{axes,manifest}.json`,
`build/b44-batch/results.json`). Both arms compile in 3.53 seconds total, have
952 bytes, 37 blocks and 46 ordered relocations, and pass the runner's exact
check with no rejections or sibling regressions. There are exactly two
requested arms and both are present; the generator's source-candidate limit
message is not a truncated source-axis product. No state probes are retained.

After integration, independent native comparison of
`build/b44-advmgr-before.obj` against `build/objdiff/base/SOURCE/ADVMGR.obj`
passes all 95 emitted functions and all allocated sections, including full
ordered relocation identities/addends (`build/b44-native.log`).
`check-function.py SOURCE/ADVMGR 0x1c47` independently passes every byte,
size, DIR32 site and ordered target against genuine pinned retail
(`build/b44-retail.log`). The deletion operand at function offset `0x38c`
still targets `??3@YAXPAX@Z` at retail VA `0x004d68c2`.

This compiler's ordinary call to scalar operator delete therefore cannot
distinguish these source spellings for this trivial array. It is not evidence
that the developers used a mismatched delete. Prefer the array-correct source
when recovering the owner. The [measured codegen pattern](../patterns/trivial-array-delete.md)
includes the actual bytes; the source alternatives are preserved in
`docs/matching/advManager-Close/visibility-array-delete.cpp`.

`homm2 build` and all 877 selftests without skips pass
(`build/build-b44.log`, `build/selftest-b44.log`).
