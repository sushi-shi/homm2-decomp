# CP02: counted event-index owners

The three adjacent count/index pairs in `game` are now packed
`GameEventList<Capacity>` records. Each record contains the actual `u16 count`
and its existing `u16 indices[Capacity]`; no storage, padding, validation or
behavior was added. All named consumers are in `GAME.cpp` and were migrated.

Six save/load calls previously passed the address of a two-byte count to a
four-byte transfer. They now pass the containing event record. The serialized
prefix remains **four bytes**, including the first index, followed by `count`
indices starting at that same first index. Removing the duplicate index would
change the format and was deliberately not done.

| Record | Capacity | Size | Offset in `game` | Index offset |
|---|---:|---:|---:|---:|
| Rumour | 30 | 62 | 25815 | 2 |
| Time | 50 | 102 | 25877 | 2 |
| Map | 50 | 102 | 25979 | 2 |

The baseline offsets were extracted from the unchanged parent declaration before
editing. VC6 and both Clang dialects independently verify these offsets, the
following window/result at 26081/26085, and the unchanged 26127-byte `game`.

## Remaining findings

This removes six **cross-member transfer bases**, not six whole-function
findings. SaveGame and LoadGame remain open: setup/campaign prefixes still cross
their declared members; file-controlled counts can exceed capacity; other
size, string, allocation and short-I/O contracts are unchanged. The record
recovery does not make malformed files safe. Thus the out-of-object function
count remains 66 at this checkpoint.
