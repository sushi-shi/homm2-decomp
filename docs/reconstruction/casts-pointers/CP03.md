# CP03: Overview row owners, measured but not retained

The real existing `OverviewTextWidgetRow` and `OverviewIconWidgetRow` aliases
each describe 70 widget pointers. A coordinated structural candidate changed
both globals to pointers to those rows, changed allocation casts, and replaced
all flat address expressions with `[row][item]` indexing. It kept the retail
11200-byte allocations, four active rows, cleanup and initialization order.
The full exact patch is archived in `docs/matching/casts-pointers/cp03-overview.cpp`.

This compiles, but does **not** preserve the retail instructions. In
SetupDynamicStuff's first cleanup block and Overview's initialization block,
VC6 changes the address calculation:

| Retail | Typed-row candidate |
|---|---|
| multiply row by 70 | multiply row by 280 |
| scaled LEA adds four times that result | ordinary ADD adds that result |
| load/store using a separate four-byte slot index | same slot width, different register lowering |

This is an actual instruction difference, not merely the expected decorated
name change for pointer-to-array globals. The full build drops from1727/1727
to1725/1727 exact functions. Overview retains its42-block flow skeleton;
SetupDynamicStuff's emitted partition is235 vs234 blocks. Neither block counts
nor equal logical indices establish byte equality.

The candidate was restored using its exact inverse; CP01/CP02 were preserved.
No compiler steering or arithmetic hidden in a new helper was retained.
This rejects one natural structural version in the current parent, not every
possible row/accessor reconstruction. Both address findings remain open.

Bounds remain distinct: cleanup/init use four rows of70; constructed rows use
at most58 icon and18 text slots. Other negative-top/stale-index contracts in
Overview are not cured by changing the pointer representation.
