# CP01: town purchase and statistics conversions

Parent: `36ace4cae`. This batch removes **20 redundant numeric casts in three
functions**: 18 in `townManager::BuyBuild`, one in `GetCategoryStats`, and one
in `SortStats`. It closes their three pinned cast findings, not the remaining
town-manager findings or the other reconstruction categories.

## Recovered conversion ownership

`BuyBuild` already declares seven signed-byte resource IDs and seven signed
16-bit costs. The five building-cost branches assign their resource cursor
directly to the byte array and their table value directly to the short array.
Those destinations still perform the same narrowing. Resource indices follow
the existing seven-resource loops; this change does not validate arbitrary
cost values, building IDs, or table indices.

The other eight removed casts surround widget geometry: description y/height,
amount-label x/y/width, and resource-icon x/y/width. Both actual widget
constructors take `i16` x, y, width, and height in
`include/BASE/textWidget.h` and `include/BASE/iconWidget.h`. Parameter conversion
supplies the same narrowing; no widget signature, owner size, arithmetic, or
allocation was changed.

`GetCategoryStats` writes the player cursor to its actual `i8* order` output.
`SortStats` similarly writes the temporary to that byte output. The latter
retains its `i32 temporaryOrder`: the credible alternative of recovering a
byte-sized temporary was measured and changes the instruction sequence.

The two `BuyBuild` `H2_ALLOC`-to-`char*` conversions remain actual erased-storage
boundaries. The functional `BuildingSlotType(index_h)` conversion remains the
building-domain boundary at `GetBuildingName`; `IDX` accesses retain strict
enum-domain handling. Closing the cast findings does not mean zero written
casts or eliminating legitimate conversion boundaries.
