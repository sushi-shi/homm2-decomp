## S34: the 52-byte reservation is not a disposable ten-byte tail

`playerData::Write` (`0x4bff0`) clears48 bytes and writes42 bytes from its
52-byte local. `Read` (`0x4c22b`) reads42 bytes into the same-sized reservation.
Only the42 serialized bytes are observed by C++ callers, but deleting the
remaining reservation changes the retail frame and its accesses.

The complete writer family tested these safe `(capacity,clear)` arms:
`(52,48)`, `(52,42)`, `(48,48)`, `(48,42)`, `(44,42)`, `(42,42)`.
The reader family tested capacities52,48,44,42. Neither matrix includes a
clear larger than its destination. They completed6/6 in8.493s and4/4 in5.609s,
without truncation, and restored source. No AST or TU-state probes were mixed
into these finite layout families.

All writer arms remain571 bytes/27 relocations; reader arms remain556/26.
Only each original arm passes the matrix's strict target-local comparison.
Writer scores are100,99.995260,99.872040,99.867300,99.867300,99.867300;
reader scores are100 then99.873170 for each compact arm. These percentages
do not excuse changed stack offsets. The writer's baseline one-block/211-
instruction topology and reader's one-block/205-instruction topology remain
useful diagnostics, not closure criteria.

## C35: use the enum's numeric value in floating arithmetic

`game::SetupPuzzlePieces` (`0x4cb1e`) now divides its floating numerator by
`IDX(PUZZLE_INTERPOLATION_TERM_COUNT)`, instead of explicitly casting that
constant to float. The constant is2, exactly representable as float. Usual
arithmetic conversion gives the same floating denominator. `IDX` keeps the
strong-enum build's domain boundary explicit; the real double conversion
of the obelisk count and floating-to-integer result conversion remain.

The complete cast/promoted matrix completed2/2 in3.756s, source restored,
no truncation. Both arms have541 bytes,20 relocations, the same text hash
`91442f4bf809b2c5`, and36 exact diagnostic blocks/155 instructions. Both
matrix strict checks reject the unresolved private floating owner, so a
100% score is not presented as that verifier's closure.

Independent final `check-function.py SOURCE/GAME 0x4cb1e` proves all ordinary
bytes and DIR32 sites; its sole unresolved operand is `+0x53`, the private
constant. [The focused supplement](check-puzzle-constant.py) proves the
`d8 35` floating divide, zero candidate addend, actual retail destination
`0x004ea4e4`, and equal four-byte payload `00 00 00 40` (single2.0).
It does not change the general verifier or accept other unknown owners.

`compare-objects.py` proves all102 emitted GAME functions plus every allocated
section and complete ordered relocations/addends unchanged from the clean
control. The full build passes1727/1727 live functions and291987 data bytes.
