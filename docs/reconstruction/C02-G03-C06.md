# C02 cursor owners; G03 and C06 measured alternatives

## C02: byte owners, not repeated erased views

The two 96-entry `cColorBits` and `cAndBits` arrays now hold `u8*` in their
definitions and owner-header declarations. Their constructor initialization,
Close disposal and complete SetPointer allocation/read/mask-building paths
were reviewed together. There are no other named consumers. These are byte
buffer owners, not opaque Win32 handles: Win32 receives the mask through the
real `BITMAP::bmBits` member.

Four repeated byte-view casts disappear; two allocation-boundary casts are
introduced where `H2_ALLOC` returns `void*`. Net reduction: two written casts.
The two physical arrays remain 384 bytes each, at 0x005355d4 and 0x00535ee0,
with unchanged section, offset, storage class and initialization. Only their
declared COFF type spellings change from `PAPAXA` to `PAPAEA`.

The 32-by-32 color scan fits 1024 bytes. Each mask plane uses 32 rows times
four bytes; the second plane starts at128, and both fit256 bytes. Valid cursor
type/frame, successful allocation and coherent resource lifecycle remain
contracts. The type index is used before the combined cursor-index assertion;
this change does not claim that retail validates every invalid input.

The complete four-arm assertion matrix separately replaced each pointer-to-i32
handle assertion with a nonnull comparison. Both alternatives preserve truth
semantics but change native text: original1376 bytes; individual changes1384
and1385; both1393. Both casts remain. No SDK handle type is changed.

## G03: preserve the color-path cleanup jump

The complete two-arm product compares the original shared `done` tail with a
structured if/else enclosing the monochrome cursor path. Both execute the
shared RestorePosition/reentrancy cleanup, but the structured arm emits1372
bytes instead of1376. The original goto remains; this rejects that measured
family, not every possible source reconstruction.

## C06: preserve the explicit fizzle lookup width

The lookup combines two u8 values into0..65535. Removing the final u16 cast
does not change the value domain, but the complete two-arm product changes
FizzleForward from1133 to1128 bytes. The original cast remains. Both actual
768-byte palettes and the65536-byte lookup owner retain their dimensions.
