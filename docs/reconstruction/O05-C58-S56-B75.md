## O05: use the actual two-dimensional effect owner

`gArmyEffected` is a real `b8[2][20]` at retail VA0x005265b0, not an untyped
forty-byte allocation. Its KB definition and X_GLOBAL declaration agree;
`COMBAT_ARMY_SLOT_COUNT` and `KB_ARMY_EFFECT_COUNT` are both20.
Fireball and MeteorShower each read/write the second side through a pointer
into the first twenty-byte row. ClearEffects does the same for its writes.
Replace all five expressions with `gArmyEffected[side][slot]`. No global
layout or ABI changes. ChainLightning, its target search, ShowMassSpell,
SPELLAI's area consumer and ARMY's splash consumer already use proper rows.

The independent read/write products are4/4 for each damage function and2/2
for ClearEffects. All arms have identical function bytes and normalized
ordered relocations in the tested clean TU state:

| Fireball | 1352 | 51 | 59 | 4.770s |

| ClearEffects | 82 | 1 | 9 | 1.604s |

Both Fireball references retain zero-addend VA0x005265b0 at function+0x3dc
and+0x41a; MeteorShower retains it at+0x271 and+0x2a9. Final exact retail
bytes, complete DIR32 sites and ordered targets pass. The three anonymous

## B75: concrete retail behavior and remaining contracts

**DrawBolt:** the red-table case sign-extends an unsigned framebuffer byte.
Retail function+0x256 contains `0f be 0c 02` (`movsx ecx,byte [edx+eax]`),
then+0x274 contains `8a 89 <address>` with the operand at+0x276 targeting
gColorTableRed VA0x004f8998, addend0. Thus values128..255 produce negative
indices relative to this256-byte owner. Full1141-byte/site/target proof
passes. This is not a redundant cast: removing it would alter retail
behavior. Normal reachability of those pixels in this mode remains open.
Other palette modes require width<=10 for the five-entry symmetric red
beam and width<=15 for rainbow indexing; guarded pixel coordinates do not
prove these separate palette-table bounds.

**Armageddon:** effect/original palette locals are zeroed at function+0x17d
and+0x184. The no-show conditional at+0x192 jumps to+0x864, skipping
creation; calls at+0x8a0/+0x8ab then use those same locals for `palette::Data`.
Data's complete17-byte retail function dereferences its real data member.
CastSpell's case calls Armageddon without a local no-show guard. These
specific branch/call operands and the entire ordinary2660-byte body match
retail; EH-helper/FS-relative closure has the same limitation as DoBolt.
No assertion that a normal gameplay caller reaches this path is made.
Both army counts zero would also leave target1 unassigned before PowEffect.

**Resurrect:** after finding a matching corpse, each later loop iteration
continues overwriting the live occupant fields. The shifted corpse entries
copy only side/index, not frame. The count decrement is unconditional even
if the search found no matching record. This exact1426-byte sequence and
all sites/targets are verified, including75f. Correcting its behavior is
not a reconstruction cast/layout fix. Legal corpse ordering and caller
success contracts require follow-up; malformed-state reachability is not
assumed merely from a possible source path.

**Animation owners:** VaporizeCreature requires every rounded-stripe final
index in0..479. RippleCreature checks waveIndex but not its fade memset
range, which starts at giMinExtentY-1. No extra leading byte is invented.
DoBlast divides by segmentCount before drawing; count0 is invalid and
count1 makes its first frame(-1)/1 equal-1. AddBolt's coordinate clamps
bound squared distance, but coincident endpoints yield a zero divisor in
ResetBoltAngle. Those checks are not repaired by removing numeric casts.

**Genuine arrays:** Fireball uses exactly19 short slots, MeteorShower seven
integer slots, mass spells2x20 flags, and Earthquake at most4 wall+4 tower+2
keep impacts=10. Both shake loops use real15 XY pairs. Their fixed offsets,
clipped copy widths and extra one-row margin keep copied pixels and final
row cursors inside real640x443 buffers, provided those buffer owners exist
and do not overlap. Resource/frame counts and valid side/army/hex/hero state
remain per-function caller contracts, not blanket validation claims.
