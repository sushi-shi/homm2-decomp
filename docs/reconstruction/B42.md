# B42: DirectPlay caller and input extents

## Shutdown drain: retail-confirmed destination hazard

`dpnet_term` supplies `drainBuffer[100 + sizeof(i32)]` to `dpnet_rcv` with a
nominal capacity of100. The callee ignores capacity, copying the queued count.
That count is the successful DirectPlay receive count, whose configured limit
is256. Thus a queued data packet larger than104 bytes exceeds this caller's
buffer, independently of the one-byte source overread already proved in B20.

The scoped checker proves all237 bytes, complete DIR32 sites and every ordered
target of `dpnet_term`, RVA `0x36be8`, against the pinned genuine retail image
(`build/b42-drain-retail.log`). Its frame evidence is:

| Function offset | Bytes | Meaning |
| --- | --- | --- |
| +0x03 | `83 ec 70` | reserve112-byte frame |
| +0x5c | `8d 4d 98` | destination address is EBP-104 |
| +0x5f | `51` | push destination |
| +0x60 | `ba 64 00 00 00` | capacity argument100 |
| +0x65 | `33 c9` | position argument0 |
| +0x67 | `e8` plus REL32 operand | call `dpnet_rcv`, retail VA0x00436dec |

The destination reaches the saved frame pointer after104 bytes. The two lower
frame temporaries do not provide additional space above the destination.
The exact original source declaration extent cannot be recovered just from
alignment, but a larger backing object cannot be asserted across that frame
boundary. `build/b42-drain-disasm.log` records the corresponding native bytes;
the independent full-function check establishes their retail equivalence.

`dpnet_rcv` and `dpEvaluateMessage` have separate full-byte/target proof in
[B20](B20.md). No packet is injected and no runtime overflow is needed for this
extent argument. Enlarging the local, capping the copy, or changing the queue
count would change existing binary behavior; none is applied as reconstruction.

## Remaining contracts

- Session enumeration writes `lSessions[iMaxSession++]` without checking its
  ten-element owner. `dwMaxPlayers=6` limits players in one session, not the
  number of sessions returned by the callback.
- Packet dispatch lacks a minimum tag byte and tag-specific payload-length
  checks. Startup fields replace player count/position/mapping values directly.
  Guest admission and transport player indices need protocol/lifecycle proof.
- Receive errors other than no-messages enter DPSD, whose reentry guard can
  return; dispatch can then see modified length or stale output data.
- Provider enumeration retains borrowed GUID pointers and uppercases the
  callback's name buffer. Their SDK lifetime and mutability contracts still
  need authoritative evidence.

These are separate pending reviews, not claims that every ordinary call is
invalid. The fixed formatter buffers checked in the function ledger do fit
their known templates/arguments.
