# C03: executive text has character-array owners

The executive's18 text slots now have separate `static char[]` owners and
source DATA annotations at their existing addresses. Every consumer names its
actual character array. The `char[604]`-to-`SExecutiveText` reinterpretation
macro is gone; no aggregate object is accessed through character-array storage.
The slot capacities remain the existing declarations, totaling604 bytes.
The original developer's declarations are not recoverable merely from these
aligned strings; these are explicit, byte-proven reconstructed reservations.

Read the complete EXEC.cpp, all18 field/capacity declarations in EXEC_TYPES.h,
and every text consumer: InitSystem, DoDialog, PrintManagerList, CallManager
and Terminate. The other five physical executive methods do not use the text
owner. All13 compiler-emitted functions, including initialization helpers,
are covered by native comparison.

## Structural families and storage evidence

All products completed, restored their inputs, and had no timeout/truncation.
These are independent structural families, not an unchanged-source island
census. Full source products and per-arm byte/relocation/block results are in
`docs/matching/early-owners/c03-executive-*.cpp`.

| Family | Arms | Result |
| --- | ---: | --- |
| Character overlay / actual initialized record | 2 | Every function remains identical; the record changes `.data` alignment4 to8. Reject record. |
| Record packing default/1/2/4 | 4 | All four retain alignment8 and604 bytes. Packing does not repair the storage difference. |
| Record / inferred-length strings / existing-capacity strings | 3 | Separate strings retain alignment4. Inferred lengths leave `.data`603 bytes; existing capacities retain604 bytes and the full native graph. Retain existing-capacity strings. |

The initial target-only exact result did not prove the data owner. The
all-section check caught the alignment change before acceptance. None of the
packing probes is retained, and no alignment directive, padding symbol or
overlapping alias is added. The existing-capacity strings include their own
zero-filled tails, with no new bytes or enlarged buffers.

## Final proof

`homm2 redelink` regenerates all18 owner identities (`build/c03-redelink.log`).
`homm2 build` then passes all gates,1727/1727 function checks and
291987/291987 data bytes (`build/build-c03-final.log`). The intermediate
1722/1727 report was the expected old-owner inventory mismatch, not a code
regression and not accepted as final evidence.

`check-executive-text.py` compares all98 native objects and1826 emitted
functions, allocated-section bytes/attributes and complete ordered relocation
graphs. It permits exactly18 explicit old-owner-plus-field-offset to named
string-owner rewrites. It verifies each new symbol's section, physical offset,
storage class and complete string bytes first; every other byte and relocation
remains strict. Final result: PASS (`build/c03-final-native.log`).

Its `--retail-data` mode checks each generated DATA address and declared extent
against the hash-pinned genuine retail image: all18 reservations/all604 bytes
agree, including zero tails (`build/c03-final-data.log`).

All five text consumers independently pass complete retail bytes, sizes,
DIR32-site lists and ordered owner-relative targets with no unknown-owner

PrintManagerList172/0xc5240; CallManager124/0xc5500; Terminate21/0xc5700.
Relocation/block reviews are preserved alongside each
`build/c03-final-<RVA>-retail.log`.

## Unchanged contracts

DoDialog's three20-manager save arrays still depend on a bounded manager list
(B03). PrintManagerList still passes32-bit pointers to `%d` in the retail ABI
and depends on terminated manager names fitting gText (B04). These are CRT
varargs calls, not manual argument-slot traversal. Splitting the text owners
does not establish those caller contracts or change retail behavior.
