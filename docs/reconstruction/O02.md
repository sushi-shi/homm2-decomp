# O02: separate pathfinding scratch storage

`SeedPositionState` bundled 29 scratch objects plus two unused four-byte padding
arrays into a 140-byte global record. No operation copies, passes, or indexes
the record as a whole. The reconstruction now names each scalar, eight-element
direction array, and nine-byte `searchNode` as file-static storage, removing
the unobserved padding objects. Genuine packed node flags remain unchanged.

The verified retail image **agrees with every original record field address**.
Earlier claims of a reordered retail layout or overlap with a modem flag were
wrong: they used a reconstructed executable, as recorded in [D01](D01.md).
The modem flag is at `0x00533e2c`, immediately after the original record extent.
This change removes padding-based aggregation; it does not prove whether the
lost original source used a record or separately declared scratch variables.
[Field map](O02.tsv) lists each original offset, size, and verified destination.
