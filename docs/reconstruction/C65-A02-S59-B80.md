# Combat-AI reconstruction-pattern review

All19 physical definitions in AI.cpp have been read in full, together with
the entire1090-line parent source, its numerical macros/private front-offset
enum and the complete PATH.h declaration header. There are no source-owned
data definitions or formatter/varargs bodies hidden after the final function.
Each definition has its own ten-pattern verdicts and note in the ledger.
The changed combatManager constant and its sole array consumer were reviewed;
the existing full header review receives a dependency follow-up.

## C65:20 redundant casts removed

The written cast count falls from38 to18. Fourteen removals are in
AICheckRetreat: three assignments into the already typed creature/count arrays
and eleven float destination/compound-assignment conversions. The estimated
quantity still converts its double product to i32 before the signed16-bit
store. No saturation or quantity policy is changed.

GetModLichDamage loses three float assignment casts, DoLichShot loses one,
and each walking helper loses its signed-byte speed-restoration cast. The
restoration value was loaded from that same signed-byte field. Implicit
assignment conversion remains; this is not removal of the physical narrowing.

Retained conversions have distinct roles: retreat's real double-to-integer
truncations and mixed float/double force ratio, DoCompAI's signed interpretation
of unsigned-long strength for division/comparison/archery scaling, and the
path-byte-to-CombatHexDirection boundaries. No unsigned owner is changed to
signed merely to make explicit sign-changing casts disappear.

The retreat products are separated by semantic phase: group reconstruction,
artifact contribution, force contribution and difficulty/experience/side
policy. Each product is complete for that phase in the original parent;
the combined retained source then receives full native verification. This is
not a claim to have enumerated every cross-phase combination or TU state.
In particular, integer division by20000 and200000 remains integer division
before float conversion, not a newly fractional computation.

## A02: recover the array expressions

DoLichShot's flat40-byte marker now has two real dimensions:
`u8 marked[COMBAT_SIDE_COUNT][COMBAT_AI_ARMY_SLOT_COUNT]`. All three pointer
expressions become `marked[side][index]`. The original flat owner covered the
valid accesses; this is clearer owner recovery, **not** a claimed repair of
a pre-existing first-row overrun. The complete pointer/flat-index/row product
has659 bytes for original and rows; ordinary flat indexing has656 and is not
retained. All three consumers preserve the20-byte row stride and exact stack
addressing. See the [measured pattern](../patterns/two-dimensional-array-owner.md).

AttemptAttack's three reversed `index[array]` expressions and
WalkTowardArmyFront's two now name the army array first. Each whole-owner
two-arm family preserves bytes and ordered relocations. They were legal C++
before, but obscured which object owns the indexed element. No raw pointer
offset, fake union, overlapping alias or new conversion helper is added.

## S59: recover nine boundary entries; retain measured frame debt

DoCompAI initializes exactly nine boundary bytes, then uses `hex/13` to select
a row. For valid hex0..116 this is0..8. Every stored boundary value lies in
the same117-cell array:8,21,33,46,58,72,85,99,112. The three trailing entries
of the old12-byte declaration are neither initialized nor accessed for valid
inputs.

The complete4-arm extent/unused-combat-local product shows the nine-entry
owner is native-equivalent, while deleting the unrelated unused combat local
is not. The measured size arm used COMBAT_GRID_ROW_COUNT, which is9. The
retained header instead sets the existing COMBAT_AI_CASTLE_BOUNDARY_COUNT to9;
all-consumer/native verification checks that integration explicitly.

Retail and both equivalent owners reserve the same0xac-byte frame. The nine
immediate byte stores begin at `[ebp-0x90]` and end at `[ebp-0x88]`; both reads
still use `[ebp+index-0x90]`. Compiler alignment is not replaced with an explicit
three-byte padding member. The size of the unknowable original C++ declaration
is not asserted; nine is sufficient for every observed valid-domain access.

The unused combat pointer, fifth-strength value, castle pointer, archery result,
two-element shootStrengths array, adjacent-attack hexes, walking path local and
front-path result remain. Every tested removal changes native bytes; details
are below. All result-store candidates preserve the original GetStrength,
HasArtifact and FindCombatPath calls and their short-circuit/order semantics.
No call is declared pure and deleted to make a smaller owner pass.

The other stack arrays are real: two-side masks/powers, retreat force/artifact
totals, the independent hero copy and fallback five-slot army group. The hero
copy isolates its replaced army while retaining hero stats/artifacts. Taking
its army's address is ordinary member access, not recovering an owner from
an interior pointer. U05 monster flags, U06 army-group views and U02 path storage
retain their separate existing semantics and open owner questions.

## B80: numerical and ownership contracts

The following are retained retail behaviors, not gameplay fixes:

- AICheckRetreat packs at most five living stacks from20 combat slots. Its
  groupIndex check follows each iteration, so stores use only0..4. Full-quantity
  and estimated-quantity stores still narrow to signed16 bits. High quantities
  need not remain positive after the1.2 estimate and narrowing; no new clamp
  hides that behavior.
- Above40000 force, the chance penalty is the integer quotient force/20000,
  at least2 for positive force. Retail at function+0x626 loads20000,+0x62b
  performs IDIV and+0x633 converts the quotient with FILD. Experience similarly
  uses integer division by200000 at+0x755 before FILD at+0x75d. For nonnegative
  experience the capped bonus is0 below200000 and0.03 above that threshold.
  The original positive upper chance clamp and lack of lower clamp remain.
- The final retreat divisor is the sum of both signed force words, with no
  intervening zero test before the x87 divide at+0x801. Valid finite force
  calculations and a nonzero representable sum are needed for a meaningful
  ratio. No claim of an integer divide-by-zero crash or normal-game zero-force
  reachability follows. FightValueOfStack's complete body was revisited for
  its quantity, hero and spell-data assumptions; those are not universally
  discharged by a nonnull hero pointer.
- DoCompAI's castle branch reads the attacker hero's archery byte without
  first checking that hero pointer. Native/retail COFF0xb50 loads the pointer
  and0xb56 reads member0x75. A later null check in the unused archeryBonus
  expression cannot protect this earlier read. CheckGetAIMove calls the AI
  after two retreat checks; it does not add an attacker-hero null guard.
  Normal-game reachability of a null attacker in castle combat is unproven.
- DoCompAI's flyer tactical branches make the same ordered six category
  attempts on either side of the strength comparison. They are not silently
  merged. Other walkers use that strength state for different movement policy.
  Its unused incoming side parameter is likewise not substituted for the
  actual m_currentSide/m_currentArmySide ownership.
- The boundary row read occurs before ValidHex, and targetCell is formed before
  that call. The nine checked constants establish a valid target pointer for
  valid source hexes; arbitrary source hexes do not have that protection.
- DoLichShot clears all40 marker bytes per candidate. It bounds neighbor hexes
  before reading cells, but non-sentinel occupant side/index still need to be
  in0..1/0..19. Wide occupants are marked once. If no live enemy candidate is
  found, this helper leaves the global action unchanged; callers rely on
  their live-combat/action lifecycle rather than a new fallback here.
- GetBestArmy's best strength begins at0 and uses a strict greater-than;
  GetWorstArmy begins at999999999 and uses strict less-than. A nonempty mask
  alone does not guarantee selection. GetClosestArmy ranks distance*1000
  minus target quantity*HP and uses its own initial9999999 cutoff, not an
  unconditional nearest-neighbor return. These exact comparisons are retained.
- Mask loops rely on valid side/counts<=20. Unsigned shifting of a single bit
  is then within the low20 bits. AttemptAttack's selected slot and
  AttemptAdjacentAttack's returned occupant index must remain valid for their
  signed `1 << index` expressions. The latter checks destHex>=0 locally but
  trusts ValidAttack for its upper bound and occupancy result.
- Walking temporarily uses speed127, restores the original signed byte, then
  consumes the real path directions. FindCombatPath checks source/target hexes
  after its setup and Clear, has a256-entry path owner and an increment cap.
  Clear resets path length; the inspected explicit failure routes precede
  backtracking. The walking helpers use path length, not solely the return
  value. The front helper's unused result is therefore recorded, not used to
  invent a new guard or claim a proven mismatch between success and length.
  Both walkers check only positive next hex before moat indexing; valid path
  directions, resulting hexes and search lifecycle remain caller contracts.

All19 bodies have no manual varargs, text formatter, owner-from-member recovery
or fabricated out-of-object pointer model. Numerical overflow, IDs, live
manager/hero pointers, actual array indices and U02 path-storage lifetime remain
explicit per-function bounds obligations. A successful native comparison proves
preservation, not malformed-state safety.
