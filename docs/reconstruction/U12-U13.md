# U12/U13: town ownership and the daily construction bitset

Removed both duplicate game-state unions. The packed game object now has
one signed `m_townOwners[72]` array and one unsigned-byte
`m_townBuiltToday[9]` bitset. All direct accesses use those owners, without
alternate member names or compensating casts.

## Meaning and complete consumer reconciliation

The former `m_castleOwners` and `m_townOwners` members had exactly the same
signed-byte type and extent. Initialization fills the table with the no-owner
sentinel; ClaimTown writes the player ID and town::Deallocate writes no-owner.
AI and map/radar consumers compare the same stored value against player IDs
and negative sentinels. SaveGame and LoadGame transfer all 72 bytes. Signed
loads and the negative sentinel are preserved; town records remain separate.

The former `m_dailyEventFlags` and `m_knownTowns` names obscured one purpose:
whether a town has already constructed a building this day. BuildBuilding
sets the town's bit. CanBuild rejects construction when that bit is set, and
CastleHandler displays the corresponding already-built-this-turn message.
Overview, adventure locators and quick-view code display the same marker.
SetupOrigData and PerDay clear all nine bytes; save/load transfer all nine.

The char view had no scalar character reads or writes and no escaping char
pointer. Its consumers were memset, read/write and BitTest's const-void input.
The other view already used u8. The single u8 byte owner therefore removes
the artificial alternate interpretation without adding a conversion.

The complete named-member census covers 17 functions across eight TUs;
14 bodies change and three already used the retained town-owner name.
No old field names or old flag-count constant remain in source or headers.
The unrelated serialized town record, hero record and event records are not
merged into these arrays.

## Layout and verification

The actual VC6 compile-only `game-town-layout-probe.cpp` proves:

| Member | Offset | Extent |
| --- | --- | ---: |
| m_castleRecs | 0x0b53 | 7200 bytes |
| m_townOwners | 0x2773 | 72 bytes |
| m_townBuiltToday | 0x27bb | 9 bytes |
| m_heroRecs | 0x27c4 | 13500 bytes |

The game object remains 0x660f bytes. Reference-binding checks prove signed
i8 owner elements and u8 bitset elements. `check-game-town-layout.py` checks
all eight consumer TUs in both supported language dialects, including these
offset, size and type assertions (`build/u12-layout.log`). All pass.

The structural change passes strict native comparison against clean053271d7:
all 98 objects, 1826 emitted functions, allocated bytes, section attributes
and ordered relocation graphs, with no new normalization exceptions
(`build/u12-native.log`). The full build passes 1727/1727 function checks and
291987/291987 data bytes (`build/build-u12.log`).

All 17 direct consumers independently retain their exact ordinary retail
bytes and sizes. Eight also fully pass the general DIR32-site and ordered-target
checker. The other nine retain its existing private-floating-constant,
EH/FS-relative or CRT-name-identity gaps. These are explicitly recorded per
consumer in [U12-functions.tsv](U12-functions.tsv); whole-native equivalence
is not mislabeled as a complete independent retail proof for those nine.
No checker exception was added. Full semantic dossiers and scoped comparisons
are retained as `build/u12-<RVA>-before-*` and `build/u12-<RVA>-after-*` logs.

This is structural type/ownership recovery, not a source-spelling permutation.
The separately measured initialization-cast cleanup is recorded in
[C34-setup.md](C34-setup.md). After retaining it, all 98 native objects, the
full build and every layout/dialect check pass again. All 17 scoped retail
comparisons retain the same results (`build/u12-<RVA>-final-*` logs).

## Bounds and remaining findings

Town IDs still require 0..71: this selects a valid owner entry and one of
72 bits in nine bytes. The bit helpers do not validate negative or oversized
IDs. Loaded data, owner/player domains, map metadata and town-list consistency
retain their existing per-function contracts. Save/load length/error handling
and cross-member prefixes are still B57; this change does not harden them.
No new allocation, extra padding, fake owner pointer or gameplay behavior is
introduced. S35's unrelated unnamed game-layout regions remain unresolved.
