# B50: hero formatter capacities

The HERO formatter outputs fit their declared buffers **for valid table indices
and a name terminated within `hero::m_name[13]`**. Those input contracts remain
B49; this result does not prove arbitrary loaded records safe.

Capacity correction from the full `X_GLOBAL.h` review: `gText` is declared as
768 bytes at `0x00524ad0`, not 500. The earlier 500-byte tests were conservative
but mislabeled as the declared capacity. No source buffer was changed; all
numerical output bounds below are unchanged.

`check-hero-text.py` reads the hash-pinned retail executable's actual pointer
destinations and strings. It also verifies the current HERO object's private
literal references against the retail operand destinations. Bounds count bytes
in the original encoding, include NUL, and allow eleven characters for any
signed 32-bit decimal argument unless a tighter branch-local fact is stated.

| Output / owner | Maximum bytes including NUL | Capacity |
| --- | ---: | ---: |
| Status bar, all 25 table entries | 70 | 768 |
| Level-up stat / one-choice / two-choice scratch | 15 / 43 / 77 | 200 |
| Complete level-up message | 128 | 768 |
| HeroHandler mana / experience dialogs | 263 / 80 | 768 |
| Secondary-skill bonus / ordinary description | 169 / 181 | 768 |
| Spell-scroll description plus spell name | 104 | 768 |
| Hero title / icon filename / decimal integer | 28 / 20 / 12 | 768 |
| Spell-point fraction / skill bonus / split prompt | 24 / 22 / 26 | 768 |

The table sizes and maxima are independently reproducible from:

| Retail pointer table | Entries | Longest string, excluding NUL |
| --- | ---: | ---: |
| Artifact names `0x004fd7ac` | 103 | 28 |
| Stat names `0x004fdc80` | 4 | 10 |
| Alignment names `0x004fdca0` | 8 | 12 |
| Plural creature names `0x004fded0` | 66 | 21 |
| Hero status templates `0x004fe524` | 25 | 31 |
| Level templates `0x004fe764` | 3 | 19 |
| Spell names `0x004fec04` | 65 | 20 |

| Secondary-skill names `0x004fed14` | 14 | 12 |
| Skill descriptions `0x004feef0` | 42 | 180 |

The 42 ordinary skill descriptions have no conversion markers, so their
no-argument `sprintf` calls do not consume nonexistent varargs. The scroll
description is entry 86 of `0x004fd948`, with precisely one `%s`. Other artifact
descriptions are forwarded directly, not formatted by `ViewArtifact`; their
literal percent characters are not interpreted at this site.

For `CheckLevel`, the prefix is at most 38 bytes. Exactly one of the four
initially zero stat bonuses becomes 1: the nested if/else is exhaustive and
exclusive. Thus exactly one stat suffix is appended. The final alternative
adds either no skill suffix, one suffix, or the two-choice suffix—not both.
The total bound is `38 + 15 - 1 + 77 - 1 = 128`.

Its tier index is intentional: before awarding the skill, a stored level of
0, 1, or 2 selects the next tier's text at index 0, 1, or 2. Existing-skill
offers require a level below expert (3), and the new-skill arm requires 0.
The special Wisdom offer also excludes expert. In contrast, the overview and
skill-detail dialog describe an already held skill and subtract 1. This is
not an off-by-one defect for valid 0..3 skill records. Invalid negative stored
levels can still pass the offer test; B49 remains open.

Whole-function `check-function.py` passes every byte, DIR32 site and ordered
target for CheckLevel (1699 bytes), status bar (1858), HeroHandler (2490),
SetupHeroView (2310), ViewArtifact (139), and DoSSLevelDialog (221).
`DoHeroSplit` still has unrelated EH aliases in that checker; only its genuine
literal destinations and output bounds are asserted here, not independent
whole-function closure. Evidence logs are `build/b50-*-retail.log`,
`build/c27-retail.log` and `build/b50-text.log`.

Disposition: retain the actual buffers. There is no evidence here for enlarging
them or fabricating a stack aggregate. Keep name termination, record indices,
shared `gText` lifetime/reentrancy and downstream widget ownership as separate
contracts; these numerical bounds do not resolve them.
