# U05: single monster-value and flag owners

Removed four redundant union definitions from tag_monsterInfo: the single-arm
outer wrapper, the identical fightValue/randomValue integer aliases, and the
two nested flag unions. The unused two-byte flag view is also gone. The record
now has one signed32-bit fightValue and one32-bit MonsterFlags attributes word.
No casts, replacement overlays, padding or alignment directives were added.

All168 affected member accesses in70 physical functions use those same fields:
six randomValue reads become fightValue;162 flag accesses use attributes.
The existing attributes/fightValue consumers do not change. The full source
and header census includes both dot and arrow access and finds no remaining
removed member, address-of-flag-subrecord consumer or byte-view consumer.
The [per-function evidence table](U05-functions.tsv) names every changed body;
its earlier ten-pattern review remains in the main ledger.

These are same-type aliases, not tagged alternatives. The monster's database
value drives both army valuation and random-monster selection; no distinct
random value is stored. Runtime effects update the same flags copied from the
database, and existing attributes consumers already read and modify that word.
Bit names retain their context-specific meanings and numeric values.

## Layout and initialization

The packed record remains26 bytes: cost at0, fightValue at2, iconIndex at6,
spriteName[5] at17, attributes at22. The containing army remains0x482 bytes,
with its monster at0xba. `monster-layout-probe.cpp` checks those offsets and
widths under the actual VC6 compiler (`build/u05-layout-final.log`). It is a
compile-only fixture, never linked into game code.

All66 initializer records were read and their obsolete grouping braces
removed without changing any value. `check-monster-record.py` compares the
complete1716 candidate bytes at004fa460 with the pinned retail image and
checks that no data relocations lie inside the table: PASS. The same checker
validates all11 affected TUs under both C++98 and C++20, with explicit layout
assertions and no unreviewed project errors (`build/u05-record.log`).

identifier-spelling experiment or a claim to have searched every compiler
state. All98 native objects,1826 emitted functions, allocated-section bytes
and attributes, and complete ordered relocation graphs are unchanged:

All70 changed bodies independently match their retail ordinary instruction
bytes and sizes. The general checker fully resolves all sites and destinations
for48 of them. Of the other22,21 retain pre-existing private floating-constant

expanded, and those22 bodies are not claimed fully retail-closed by this pass.

The block reader includes compiler helpers after the last game function in

Those diagnostic differences also occur before this change; the exact-sized
function/ordered-relocation checks do not include unrelated helper bodies.

compile caught both before verification. The corrected census includes them,
and every retained source and proof above is from the successful final build.

Runtime creature-index, attack/spell, loaded-record, and combat-lifecycle
contracts are unchanged. Removing duplicate views is not a bounds check,
initialization repair or gameplay change.
