# O04: the two-element walk-speed owner

Twelve accesses in `StartCursor`, `DrawCursor`, `TurnTo`, and `MoveHero`
indexed `(&gConfig.computerWalkSpeed)[gbThisNetHumanPlayer[giCurPlayer]]`.
Index one crossed from a scalar into its neighboring scalar. The owner is now
`ConfigWalkSpeed walkSpeeds[2]`, with named computer/human indices. All six
registry/default accesses and thirteen adventure-manager accesses use the
same owner; there are no compatibility unions or aliases.

## Layout and index evidence

The retail lookup is a four-byte scaled load from the beginning of `gConfig`.
Preference reads/writes and UI/default assignments independently identify
offset zero as computer speed and offset four as human speed. Replacing the
two four-byte fields with an eight-byte array preserves every later offset
and the packed `configStruct` size of `0x1a0`.

All writes to `gbThisNetHumanPlayer` were inspected: GAME initialization/load
assign true or false; KB clears its six bytes and sets the local-player entry
true; `ShowComputerScreen` saves, sets true, and restores one entry. Static
initialization is zero. Consequently a valid player entry selects zero or one.
Player-index validity and malformed registry speed values remain separate
input-domain concerns (B43); this change does not claim to validate them.

## Native and retail proof

The isolated before snapshot is `build/o04-before/`, taken after C18 and before
any O04 source edits. `build/o04-proof.py` applies the existing
`compare-objects.py` census to every object in both trees: **98 TUs, 1,826
emitted functions, no differences** in instruction bytes, ordered relocation
sites/types/identities/addends, or any allocated section. Only established
compiler-private symbol normalization is used. The report is
`build/o04-whole-native.log`.

The scoped genuine-retail comparison (`build/o04-retail.log`) establishes
equal full instruction bytes and DIR32 site lists for all four changed cursor
functions, at RVAs `0x332d0`, `0x334da`, `0x33e2c`, and `0x340ca`, respectively
292, 1,501, 531, and 4,347 bytes. All ordered targets resolve directly except
the private double in `TurnTo` at function offset `0xbc`: the operand points
to retail VA `0x004ea508`, whose eight bytes independently equal the candidate
`__real@8@3fffc000000000000000` constant, `000000000000f83f` (1.5).
`build/o04-double-proof.log` records that last content comparison. No unknown
destination was silently accepted by the scoped verifier.

`homm2 build` passes (1,727/1,727 annotated functions reported exact), and
all 877 selftests pass without skips with Universal Ctags on PATH. Logs:
`build/build-o04.log`, `build/selftest-o04-full.log`. This evidence supports
the array recovery, not closure of the other cursor findings.
