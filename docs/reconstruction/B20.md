# B20: retail receive length crosses its payload allocation

This is confirmed **retail behavior**, not an inferred reconstruction correction.
All listed instructions and queue operands were rechecked against retail SHA-256
`bc7e9c9320aa3e5c1ffca6d2bfa530ecedb5a3bca1b91c959501c15ad72c329a`.
The size includes the one-byte packet tag. The data handler removes that tag
when allocating/copying but stores the original size for the receive wrapper.

| Operation | Retail site | Length |
| --- | --- | --- |
| Allocate payload | 0x004b268f..0x004b2696 | size - 1 |
| Copy from receive buffer + 1 | 0x004b26b3..0x004b26ce | size - 1 |
| Store queue length | 0x004b26e1..0x004b26e4 | size |
| Copy queued payload to caller | 0x004b2566..0x004b2583 | stored size |

The argument arrives in ECX and is saved at [ebp-0x2c] in wsEvaluateMessage:

```
004b268f  8b 45 d4       mov eax,[ebp-0x2c]
004b2692  83 e8 01       sub eax,1
004b2695  50             push eax
004b2696  e8 a0 43 02 00 call operator new
...
004b26e1  8b 4d d4       mov ecx,[ebp-0x2c]
004b26e4  89 0c 90       mov [eax+edx*4],ecx
```

The queue-length pointer is retail 0x005242d4; payload-pointer table is
0x005242d0; head/tail are 0x005242c8/0x005242cc. The receive function loads
that stored length at 0x004b2566 and passes it unmodified to memcpy at
0x004b2583. Thus even an otherwise valid data packet produces a one-byte
read past the requested payload allocation. Allocator rounding does not
establish a larger C++ object.

The incoming-buffer minimum length, message-specific payload extents, player
count/index bounds, queue-full handling and ignored receive destination-size
parameter also remain unguarded in the reconstructed functions. Those need
separate caller/retail review; this proof does not claim they are safe.

No behavioral change is applied: changing queue size to size-1, allocating an
extra byte, or capping the receive copy would change the binary/protocol behavior.
Keep this finding visible in the function ledger instead of reporting that the
bounds checklist has no remaining cases.
